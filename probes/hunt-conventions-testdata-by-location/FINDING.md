# «В тестовых данных только синтетические адреса» держится каталогом и содержимым — а данные живут не только там

**Трек:** oracle-формы (охота по конвенциям). **КЛЕТКА:** страница и инструменты × конвенция
по БД §13.5 и §17 п. 13, конвенция по API §5.8 и §14.5. **Найдено 2026-09-08 охотником.**

**Дерево менялось под замером, и это важно для чтения цифр.** `scripts/check-fixtures.py` был
отредактирован во время этой охоты: добавлены расширения кроме `.json` и три написания
windows-пути. С этой правкой прогон стража по настоящему каталогу `fixtures/` стал **красным** —
`api/config.json: real user path -> C:\\Users\\d`. Это не моя находка и не предмет этой
строки: это носитель, который нашла сама только что починенная норма. Мой замер — про то, чего
она по-прежнему не видит.

## КЛАСС

**Правило о тестовых данных исполняется по МЕСТУ ФАЙЛА и только по его СОДЕРЖИМОМУ.** Тестовые
данные же определяются РОЛЬЮ, а не каталогом, и живут ещё в двух видах, до которых
единственный держатель не дотягивается:

1. **литералами внутри наборов** `scripts/test-*.mjs` — та же роль, другой каталог;
2. **именем файла** — фикстура с безупречным содержимым и почтой в имени проходит, и почта
   при этом попадает в собственный вывод стража;
3. и это не гипотеза про имя: инструмент проекта сам просит такие имена —
   `scripts/claude_limits.py:328` ищет записанный ответ как `<offline_dir>/<email>.json`, а
   каталог по умолчанию для дифференциала (`scripts/diff_with_probe.py:91`) — это
   коммитимый `fixtures/usage`.

## Норма, дословно

`docs/conventions/database.md:444` (§13.5 «ПДн вне таблиц»):

> - **Тестовые данные** — только синтетические (`user1@example.com`, вымышленные ФИО);
>   копировать продуктив в тесты запрещено…

`docs/conventions/api.md:598-600` (§14.5) — про имя файла прямо:

> Линтер выводит из категорий полей свойства операций и падает, если поле категории `pii` или
> `subject_id` оказалось в пути, в query, **в имени файла экспорта** или в событии без пометки.

`docs/conventions/api.md:253` (§5.8): «клиентское значение не становится путём, заголовком,
ключом объекта в хранилище…».

## Замер (три прогона одного и того же стража проекта)

```
addresses hard-coded in scripts/test-reorder.mjs: ['a@x.com', 'b@x.com', 'c@x.com', 'd@x.com']

1. the real fixtures/ directory, as this run finds it
   exit=1   SECRET SCAN: FAILED
   api/config.json: real user path -> C:\\Users\\d        <- the just-fixed rule, not my line

2. the SAME strings, sitting inside a fixture tree
   exit=1   SECRET SCAN: FAILED
   usage/order.json: non-example e-mail -> a@x.com

3. spotless content, the e-mail is the FILE NAME
   exit=0   SECRET SCAN: clean
   what the guard printed about it:
     usage/firstname.lastname@customer-corp.ru.json       valid JSON, limits=0 []
```

Один и тот же набор строк — красный в `fixtures/`, невидимый в `scripts/`. Судит не свойство
строки, а каталог, в котором она лежит. А почта в ИМЕНИ файла не видна ни при какой правке
содержимого — зато печатается в отчёт стража.

**Носители в дереве сегодня** (греп по всему `scripts/` и `src/web/`):
`scripts/test-reorder.mjs:23`, `:76`, `:79`, `:96`, `:145`, `:148`, `:170`, `:172`, `:182` —
`a@x.com`…`d@x.com`; `scripts/test-format.mjs:328-330` — `A@X.com`, `a@x.COM`, `b@x.com`;
`scripts/test-render.mjs:183` — `nobody@example.net`. Домен `x.com` — живой чужой домен, а не
зарезервированный RFC 2606 `example.*`; по правилу самого стража (`scripts/check-fixtures.py:21`)
это «non-example e-mail». `example.net` тоже зарезервирован RFC 2606, но в разрешённые страж его
не включает — то есть даже правильная по норме форма судится по-разному в зависимости от того,
где лежит файл.

## ДВЕРЬ

**Двери нет: правило держит один страж, и он привязан к каталогу и к содержимому.**

1. `scripts/check-fixtures.py:19-28` — единственное машинное объявление правила (кортеж
   `secrets`), корень берёт из `sys.argv[1]`, то есть спрашивает «где», а не «что»;
2. `scripts/check-web.mjs:84` — единственный вызов, без аргумента, то есть всегда один и тот
   же каталог;
3. `fixtures/usage/README.md:5` — прозой: «No real token, no real e-mail, no real account is
   in here». Обещание сформулировано про каталог, и ровно так его исполняет машина.

Ни одно из трёх мест не отвечает на вопрос «какие данные проекта являются тестовыми» — все три
отвечают «что лежит в этом каталоге».

## ПОЧЕМУ НЕ ЧИНИТСЯ У НОСИТЕЛЯ

Заменить `a@x.com` на `a@example.com` в `test-reorder.mjs` — починка девяти строк одного
файла. Свойство останется целиком: следующий набор заведёт свои литералы, и его тоже никто не
прочитает; имя файла останется невидимым при любом содержимом; а инструмент, который просит
называть файлы почтой, продолжит просить. Обратная сторона того же: расширить стража на
`scripts/*.mjs` — значит получить красноту на `probeSummary({ … email: 'a@x' … })` в
`scripts/test-settings.mjs:138`, где адрес по смыслу не адрес; то есть починка «одним грепом
шире» тоже неверна, и решать, что здесь считается тестовыми данными, — не охотнику.

## Воспроизведение

```
sh probes/hunt-conventions-testdata-by-location/cmd.sh
```

Проба создаёт два маленьких дерева ТОЛЬКО внутри своего каталога
(`as-a-fixture/`, `name-carries-it/`), гоняет на них `scripts/check-fixtures.py` и печатает
все три стороны. Дерево проекта не трогает, сети нет.
