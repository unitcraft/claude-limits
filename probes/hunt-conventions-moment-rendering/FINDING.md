# Как страница печатает момент, решается в каждой точке показа — четырнадцать раз

**Трек:** oracle-формы (охота по конвенциям). **КЛЕТКА:** страница и инструменты × конвенция
по БД §1 и конвенция по API §11. **Найдено 2026-09-08 охотником.**

## КЛАСС

**Перевод момента в местное время — пояс, локаль и вид часов — решается в месте показа, а
не один раз.** Свойство шире найденного случая; синтаксисов, в которых оно выражено, три, и
греп по одному из них класс не находит:

1. `toLocaleTimeString([], …)` — «пояс и локаль браузера» (6 мест);
2. `toLocaleDateString('en', …)` / `toLocaleString('en', …)` — «локаль принудительно
   английская, пояс браузера» (6 мест);
3. `new Date(at).toLocaleString()` без аргументов вовсе — `src/web/stats.js:212`.

Плюс отдельное решение про часы: `hour12: false` стоит в пяти местах и отсутствует в трёх
(`src/web/app.js:292`, `src/web/app.js:561`, `src/web/format.js:214`), причём два последних —
в тех же файлах, где стоит.

## Норма, дословно

`docs/conventions/database.md:26-27` (§1 «Время»):

> Локальное время возникает лишь при показе человеку; пояс берётся из его профиля, иначе из
> настройки приложения.

Настройка приложения приезжает в ответе — `fixtures/api/snapshot-mixed.json` несёт
`"tz": "Europe/Moscow"`. Страница присваивает её (`src/web/app.js:295`:
`state.tz = snap.tz || state.tz;`) и **не читает нигде**: греп `state.tz` по `src/web`
даёт ровно одну строку — эту.

То же правило, уже разделённое по ролям, лежит в двух документах проекта.
`docs/plans/01.3-api.md:38-39`:

> пояс бэкенда для подписей — поле `tz` (IANA) в `/api/snapshot`; страница считает оси в
> поясе браузера

`docs/plans/01-widget-on-nova.md:509-510`:

> готовые подписи `*_label` считаются в поясе бэкенда, оси графиков страница строит в поясе
> браузера.

То есть **подпись** — пояс бэкенда, **ось** — пояс браузера. Страница печатает подпись
времени сброса в поясе браузера.

## Замер (обе стороны напечатаны пробой)

```
this run's zone : UTC                     |  this run's zone : Europe/Moscow
  app.js:292   fetched-at      05:50 PM   |    app.js:292   fetched-at      08:50 PM
  format.js:83 reset column    17:50      |    format.js:83 reset column    20:50
  format.js:214 footer next    05:50 PM   |    format.js:214 footer next    08:50 PM
  -> 2 different strings for one instant on one page
```

(строки напечатаны с явной локалью `en-US` — именно она приезжает в `[]`, когда браузер
американский; на этой машине локаль `ru-RU`, и там обе формы совпадают, что и делает
расхождение невидимым в здешних прогонах.)

Локаль — то же самое, на одной карточке статистики:

```
  chart.js:161 axis tick   (locale 'en')  Mon
  stats.js:286 gap caption (locale 'en')  Sep 7, 20:50
  stats.js:212 values table (no locale)   07.09.2026, 20:50:00
```

И то же поле, две подписи — серверная и своя (`TZ=UTC`, 4 из 4 расходятся):

```
  weekly_scoped  2026-09-13T07:00:00Z
     server: Sun 10:00 (5d 14h)     page: Sun 07:00 (5d 14h)
  weekly_all     2026-09-09T10:00:00Z
     server: Tue 13:00 (2d 17h)     page: Wed 10:00 (1d 17h)
```

**Два расхождения переживают любой пояс, потому что они не про пояс:** `2026-09-09T10:00:00Z` —
среда, а серверная подпись называет её `Tue`; и остаток у сервера `2d 17h`, у страницы
`1d 17h` (в другой строке фикстуры — `1h 23m` против `1h 22m`: разные правила округления).
Значит подпись и машинное поле в фикстуре уже разошлись, и ничто их не сверяет.

## ДВЕРЬ

**Двери нет: решается в четырнадцати местах, шести файлах.** Доказательство размазанности —
три адреса разного вида:

1. `src/web/format.js:83` — `formatResetMoment`, `[]` + `hour12: false`;
2. `src/web/stats.js:212` — `new Date(at).toLocaleString()`, без единого аргумента;
3. `src/web/chart.js:159-161` — три разных набора опций в трёх соседних строках одной
   функции.

Естественный дом у класса есть — `src/web/format.js`, где уже живут `formatResetMoment`,
`formatReset` и `formatDuration` и куда ходит `render.js`; но `stats.js`, `folders.js`,
`chart.js` и сам `app.js` мимо него завели по своему форматтеру: `ago` (`src/web/app.js:161`),
`shortMoment` (`src/web/stats.js:283`), `shortDay` (`src/web/folders.js:65`).

Второй адрес класса — **кто вообще имеет право рисовать подпись**. `src/web/render.js:115`
предпочитает собственный расчёт серверной подписи всякий раз, когда есть `resets_at`:

> `limit.resets_at ? formatReset(limit.resets_at) : (limit.reset_label || '—')`

а `docs/plans/01.3-api.md:695` (отклонение D2, записанное по §19 конвенции) обосновывает
существование полей `*_label` так:

> два интерфейса (страница и виджет) и дифференциал с эталоном должны показывать одну строку

То есть отклонение выписано ради одной строки в двух интерфейсах, а страница показывает
свою — и в UTC-браузере она не совпадает с серверной ни в одной из четырёх строк.

## ПОЧЕМУ НЕ ЧИНИТСЯ У НОСИТЕЛЯ

Дописать `hour12: false` в три места — починка формы, которую я назвал; свойство останется:
пояс по-прежнему берётся у браузера (а не из `tz`, как требует §1 и как делят роли оба плана),
локаль по-прежнему решается пофайлово, и следующий показ момента заведёт пятнадцатое место.
Ровно так уже случилось: `hour12: false` кто-то добавлял осознанно — он стоит в пяти местах из
восьми, где печатается время суток, — и три пропущенных выглядят починенными, потому что на
локали `ru-RU` разница не видна.
