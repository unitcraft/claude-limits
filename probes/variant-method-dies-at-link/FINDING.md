# `.method()` на голом варианте суммы: чекер принимает, линкер не находит

**Дата:** 2026-09-13, 22:11–22:12. **Класс уже заведён: реестр 221.1 №393**, открыт,
К2 («голый вариант суммы перед `.method()` резолвится в несуществующую свободную
функцию», окно p249, 2026-08-06). **Новой строки не завожу** — дом есть; эта проба
добавляет носитель и обход.

## Что произошло

Тест T4.2 писал `assert(Installed.ok())`, где `Installed` — вариант `Change`.
`nova check` печатает `ok:`. Сборка падает:

```
lld-link: error: undefined symbol: nova_fn_Installed_ok
lld-link: error: undefined symbol: nova_fn_AlreadyInstalled_ok
lld-link: error: undefined symbol: nova_fn_Removed_ok
```

Эмитируемый C называет вызов по **ВАРИАНТУ**, а не по ТИПУ, и такой функции не
эмитируется никогда.

## Ось, отделяющая причину от соседней

В `probe.nv` **обе формы в одном файле**:

```nova
ro bound = Yes
print("bound: ${bound.ok()}")   // работает
print("bare: ${Yes.ok()}")      // undefined symbol: nova_fn_Yes_ok
```

`control.nv` — тот же файл минус одна строка с голым вызовом:

| | что | итог |
|---|---|---|
| проба | обе формы | `nova check` → ok:; `nova build` → `undefined symbol: nova_fn_Yes_ok` |
| контроль | только связанная форма | собрался, запустился, напечатал `bound: true` |

Без контроля «сборка падает» не говорит, КАКАЯ форма её роняет.

## Обход, применённый в T4.2

Связать приёмник до вызова:

```nova
ro a = Installed
assert(a.ok())
```

Значение представимо — не представима только эта форма вызова. Обход записан
комментарием в `src/install/autostart_test.nv` со ссылкой на №393, чтобы следующий
читатель не принял связывание за стиль.

## Почему это не поймала проверка типов

Тот же класс, что #1082 и #1085: чекер принимает то, чего кодогенератор выразить не
может, и расхождение обнаруживается на ЛИНКОВКЕ. `nova check` зелёный про такую
программу не говорит ничего.
