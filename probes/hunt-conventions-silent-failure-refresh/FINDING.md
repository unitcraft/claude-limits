# Что показать при отказе — решает каждый обработчик; пять сетевых вызовов, пять разных исходов, один из них молчание

**Трек:** oracle-формы (охота по конвенциям). **КЛЕТКА:** страница и инструменты × конвенция
по API §17 (последний пункт) и §0.5. **Найдено 2026-09-08 охотником.**

## КЛАСС

**У отказа нет общего места.** Каждый сетевой вызов страницы сам решает, ловить ли исключение
и что сказать человеку, — и решения приняты пять раз по-разному: перебросить вызывающему,
написать в плейсхолдер, написать в заметку панели, показать `toast`, **не сказать ничего**.
Свойство шире найденного молчания: пока «сообщить об отказе» — обязанность обработчика, а не
транспорта, каждый следующий вызов заводит шестой вариант, и один из вариантов всегда «забыл».

## Норма, дословно

`docs/conventions/api.md:666-667` (§17 «Повторы на стороне клиента»):

> - исчерпав попытки, клиент показывает ошибку с кнопкой повторить, не пустой экран и не
>   вечный индикатор.

`docs/conventions/api.md:26` (§0, п. 5): «**Молчаливых исходов нет.**»

## Замер

```
every fetch() in app.js: does its own function catch, and who calls it?
  app.js:194  inside apiGet         catches      (rethrows to six call sites)
  app.js:275  inside saveOrder      NO catch
  app.js:482  inside probeFolder    catches
  app.js:512  inside saveSettings   catches
  app.js:553  inside refresh        NO catch
        called at app.js:601  refresh(e.currentTarget));
```

`saveOrder` — законный случай: он отдан в `reorder.js` как `commit` (`src/web/app.js:596`), и
там отказ пойман и озвучен (`src/web/reorder.js:94-96`, `toast('could not save order')`).
Проба его вызывающего не находит именно потому, что имя передано без скобок, — то есть
единственное место, где отказ записи доходит до человека, живёт в другом файле, чем сам вызов.

`refresh` не пойман нигде. Проба выполняет **его собственный исходный текст**, извлечённый из
`app.js` регулярным выражением и напечатанный целиком, с `fetch`, который отвергает промис:

```
the promise REJECTED: TypeError: Failed to fetch
   the click handler is `(e) => refresh(e.currentTarget)` (app.js:600-601):
   nothing awaits it, so this becomes an unhandled rejection in the console.
button afterwards: spinning=false disabled=false title="poll now"
```

Человек нажал «poll now» при недоступном бэкенде: иконка крутнулась и встала, ни строки,
ни тоста, ни отметки. По §17 это ровно то, что запрещено, — «не пустой экран и не вечный
индикатор» написано про исход, о котором сказали; здесь исход есть, а сообщения нет.

## ДВЕРЬ

**Двери нет: решается в пяти обработчиках.** Три адреса разного поведения:

1. `src/web/app.js:213-218` — `fetchSnapshot`: пишет в плейсхолдер, и только если снимка ещё
   нет («Keep the last good reading»);
2. `src/web/app.js:513-516` — `saveSettings`: `toast(...)` с текстом ошибки;
3. `src/web/app.js:550-568` — `refresh`: `try/finally` без `catch`.

`toast()` (`src/web/app.js:250`) — ближайшее, что есть на роль двери, но это функция показа, а
не место принятия решения: кто её зовёт, решает каждый обработчик сам. Отдельно замечу, что
`apiGet` (`src/web/app.js:189`) уже играет роль единой двери для ПОВТОРОВ — то есть в этом же
файле образец «одно место на транспортное правило» существует и на отказ не распространён.

## ПОЧЕМУ НЕ ЧИНИТСЯ У НОСИТЕЛЯ

Обернуть `refresh` в `try/catch` с тостом — починка одной кнопки. Свойство останется:
следующий вызов (а `POST /api/history/search` из приёмки T2.23/T2.24 ещё не написан, см.
`docs/handoff.md:64-66`) снова будет сам решать, ловить ли, и снова может не поймать. Ровно
так уже вышло: четыре обработчика из пяти написаны с `catch`, автор явно про это думал — и
пятый всё равно выглядит починенным, потому что отличается отсутствием строки, а не наличием
неправильной.

## Воспроизведение

```
sh probes/hunt-conventions-silent-failure-refresh/cmd.sh
```

Проба ничего не пишет и сети не трогает: читает `src/web/app.js` как текст, печатает
извлечённый исходник и исполняет его с подставленным `fetch`.
