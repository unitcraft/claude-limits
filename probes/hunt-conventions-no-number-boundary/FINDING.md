# Кто превращает значение с провода в число — решает каждый файл; два файла страницы решают по-разному

**Трек:** oracle-формы (охота по конвенциям). **КЛЕТКА:** страница и инструменты × конвенция
по API §11, конвенция по БД §5. **Найдено 2026-09-08 охотником.**

**ЧЕГО ЭТОТ ЗАМЕР НЕ УТВЕРЖДАЕТ, и это существенно.** Сегодняшний контракт
(`docs/plans/01.3-api.md:248`) отдаёт `percent` целым числом JSON — и это конвенции не
противоречит (§11: «целые счётчики — число JSON»). Носитель, который я показываю, **условный**:
он оживает, когда доля становится дробной. Живой половиной класса остаётся то, что у страницы
**нет ни одного места**, где значение с провода превращается в число, — и два файла из-за
этого ведут себя по-разному уже сейчас, на одном и том же входе.

## КЛАСС

**Граница «текст с провода → число» не проведена: каждый потребитель решает сам, приводить или
сравнивать как есть.** Свойство шире найденного случая — оно про любое поле, чью форму
конвенция задаёт строкой десятичного числа: деньги, количества, доли, проценты с дробью.

## Норма, дословно

`docs/conventions/api.md:512-514` (§11 «Форматы значений»):

> | деньги | строка десятичного числа + `currency_code` ISO 4217 | `"amount": "1234.50", "currency_code": "RUB"` |
> | количество, доля, процент с дробью | строка десятичного числа | `"quantity": "12.500"` |
> | целые счётчики | число JSON | `"count": 42` |

`docs/conventions/database.md:161` (§5): «В API сумма — строка `"1234.50"`, чтобы клиент не
потерял копейки в плавающей арифметике».

## Замер

```
a limit at 9 % with a forecast of 11 % at reset
  percent as JSON numbers    -> forecast ghost: 2%
  percent as decimal strings -> forecast ghost: null

the same two values through chart.js, which converts at its door:
  yOf(9)   = 60.33     yOf('9')   = 60.33
  yOf(11)  = 59.07     yOf('11')  = 59.07

render.js:83 is `fc.percent_at_reset > limit.percent`:
  11 > 9      -> true
  '11' > '9'  -> false   <- string comparison, and the ghost is dropped
```

Прогноз «11 % к сбросу при текущих 9 %» — тот самый случай, ради которого призрачная часть
полосы существует, — исчезает молча. Ошибки нет, отказа нет, полоса просто без прогноза.

## ДВЕРЬ

**Двери нет: приведение решается по месту.** Три адреса:

1. `src/web/chart.js:31` — `const p = Math.max(0, Math.min(100, Number(percent) || 0));`
   — дверь есть, у самого входа геометрии;
2. `src/web/render.js:83` — `if (fc && fc.percent_at_reset != null && fc.percent_at_reset > limit.percent)`
   — сравнение сырых значений;
3. `src/web/render.js:110` и `:76` — `Math.round(limit.percent)`: приведение есть, но своё, в
   каждой строке отдельно (в `valueText`, `src/web/render.js:33`, — четвёртое такое же).

Естественное место для двери — `src/web/format.js`, который уже объявлен «the pure arithmetic
… these are the parts that can be WRONG in a way nobody sees» (`src/web/format.js:1-6`): там
живут `clamp`, `cellGeometry` и `elapsedShare`, но функции «прочитать десятичное с провода»
среди них нет.

## ПОЧЕМУ НЕ ЧИНИТСЯ У НОСИТЕЛЯ

Поставить `Number()` в `render.js:83` — починка одного сравнения. Свойство останется: приведение
по-прежнему будет решаться в каждой строке, а тесты страницы этого не увидят, потому что все
фикстуры отдают числа (`fixtures/api/snapshot-mixed.json`, `history-7d.json`). То есть новая
форма значения не сделает ни один набор красным — она сделает картинку неправильной. Ровно
поэтому граница нужна одна, и её отсутствие — не свойство `render.js`.

## Воспроизведение

```
sh probes/hunt-conventions-no-number-boundary/cmd.sh
```

Проба поднимает DOM-заглушку проекта, рендерит одну строку лимита дважды и печатает обе
геометрии. Ничего не пишет, сети нет.
