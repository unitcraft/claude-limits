# Имя типа из моего модуля меняет смысл ОДНОИМЁННОГО типа внутри std

**Приоритет:** К1 (сборка невозможна; ошибка указывает на файл std, которого автор
не касался, и её нельзя исправить в своём коде иначе как переименованием).
**Найдено:** 2026-09-08, при написании `server/handlers/folders.nv` (claude-limits,
T2.17).
**Номер реестра:** №TBD.

## Класс

Модуль экспортирует `type Token consume`. Другой модуль импортирует **что угодно**
из него — не сам `Token`, а соседнюю функцию — и одновременно импортирует
`std.encoding.json`. У std в `encoding/json.nv` есть СВОЙ `Token` (лексер), и его
поля начинают судиться по чужому типу:

```
D:\...\nova\std\src\encoding\json.nv:362:8: error: [D133-field-marker-missing]
    field `tok` имеет consume-тип но не помечен `consume`.
D:\...\nova\std\src\encoding\json.nv:790:9: error: [D133-field-marker-missing]
    field `cur` имеет consume-тип но не помечен `consume`.
```

Обе строки — в исходниках стандартной библиотеки. Автор пакета не может их
исправить и, читая сообщение, не видит связи со своим кодом: ни `Token`, ни `json`
в его файле рядом не стоят.

**Ни один из импортов не называет `Token`.** В пробе импортируется `describe` из
своего модуля и `Json` из std. Утечка идёт от МОДУЛЯ к МОДУЛЮ, а не через список
имён.

## Проба

```
cd <repos>/claude-limits/probes/type-name-leaks-into-std
../../nova.sh check src/control_renamed.nv          # CONTROL 1 -> ok
../../nova.sh check src/control_no_json.nv          # CONTROL 2 -> ok
../../nova.sh check src/type_name_leaks_into_std.nv # -> FAIL, внутри std
```

| файл | отличие от падающего | результат |
|---|---|---|
| `control_renamed.nv` | тот же consume-тип назван `Secret` | **ok** |
| `control_no_json.nv` | `Token` есть и импортирован, но std-`json` не в CU | **ok** |
| `type_name_leaks_into_std.nv` | — | **FAIL** в `std/encoding/json.nv` |

Каждый контроль отличается ровно одним признаком, поэтому вывод — про сочетание
«одноимённый тип + оба модуля в одном CU», а не про consume-типы вообще и не про
std-json вообще.

Промежуточная ошибка пробы, названная честно: первые версии контролей падали по
своей причине — файл в корне исходников обязан объявлять `<пакет>.<имя>`, а я написал
`module control_renamed`. Пока это не было исправлено, «контроль тоже красный» ничего
не доказывал.

## Почему это больно

`std.encoding.json` — единственный разборщик JSON в дереве, то есть нужен КАЖДОМУ
обработчику HTTP-тела. `Token` — естественное имя для типа, хранящего учётные
данные. Пересечение почти неизбежно, а диагностика указывает не туда.

## Обход, применённый в claude-limits

`accounts/login.nv`: `Token` переименован в `Secret`. Имя не хуже — тип и правда
держит секрет, — но выбрано оно не по смыслу, а чтобы разойтись с лексером std.

## Чего проба НЕ утверждает

Не проверено, важна ли `consume`-природа типа: возможно, любое совпадение имён типов
между модулем пользователя и модулем std ломает разрешение, а `consume` лишь делает
поломку видимой (через D133). Контроля с обычным value-типом того же имени в пробе
нет.

## Строка реестра: №1049

Номер выдан интегратором 2026-09-08 для `nova/docs/plans/221.1-bug-sweep.md`.

**Строка НЕ является вторым замером этой пробы.** В ней прямо сказано: «прочитал отчёт и сверил цитаты с файлом, но САМ ПРОБУ НЕ ЗАПУСКАЛ». Вердикт «блокирует тег» тоже отложен: число блокеров — это мера расстояния до релиза, и двигать её чужим замером нельзя ни вверх, ни вниз.
