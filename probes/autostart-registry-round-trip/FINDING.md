# Автозапуск на Windows: форма команд проверена, ключ автозапуска НЕ тронут

**Дата:** 2026-09-13, 22:17–22:19. Карточка T4.2. Три пробы, все три — про то, чего
`nova check` о моём коде сказать не мог.

## 1. `regprobe.nv` — умеет ли код вообще различать «есть» и «нет»

Читающая проба, ничего не меняет.

| вопрос | код возврата |
|---|---|
| `reg query HKCU\…\Run` — существует ли сам ключ | **0** (значит форма команды верна) |
| `reg query …\Run /v claude-limits` — стоит ли наша запись | **1** (не установлена) |
| то же для заведомо несуществующего имени — **контроль** | **1** |

Контроль обязателен: без него «1» у нашего значения не отличить от «reg всегда
возвращает 1».

**Оболочка на этот вопрос ответить не может.** Первая попытка через bash дала
`ошибка: неверный синтаксис` — MSYS портит `HKCU\Software\…` ДО того, как `reg.exe`
его увидит. `Command.arg` отдаёт строку процессу без шелла, поэтому верен только
прогон из Nova.

## 2. `regwrite.nv` — работает ли запись, и идемпотентна ли она

**НЕ под ключом автозапуска.** Установка настоящей записи меняет то, что стартует при
входе владельца в систему, — это постоянное изменение его машины, и делать его ради
проверки нельзя. Проба берёт собственный ключ `HKCU\Software\claude-limits-probe`,
создаёт значение, читает, удаляет значение, затем ключ, и проверяет, что чтения
переворачиваются на каждом шаге. Формы аргументов скопированы из
`src/install/real_autostart.nv` слово в слово, включая `/f`.

```
before add,    query -> 1   (ожидалось non-zero)
reg add              -> 0
after add,     query -> 0
reg add again        -> 0   (идемпотентность НИЖЕ уровня логики Nova)
reg delete           -> 0
after delete,  query -> 1
key removed          -> 0
```

`/f` — не украшение: без него дочерний процесс ждёт подтверждения с клавиатуры,
которого не будет, и установка повисает, потому что эффект ждёт завершения ребёнка.

## 3. `qual.nv` — и проба, которая спасла Linux-ветку

Чтобы убрать шесть `unused-import` на Windows, я перевёл Linux-половину на вызовы по
полному пути (`std.fs.try_exists(...)`) и снял импорт. `nova check` стал зелёным —
**и это ничего не значило**: на этой машине Linux-ветка вырезана `#cfg` и не
компилируется вовсе.

`qual.nv` компилирует ту же форму безусловно. Оказалось: вызов по полному пути
резолвится, а `"путь".to_path()` — НЕТ, это расширение `str`, которое даёт `std.fs`
(«import the stdlib module that provides it»). Каждая функция Linux-ветки принимает
`Path`, значит без импорта ветка не собралась бы вовсе — на Linux, то есть там, где я
не смотрю.

Импорт вернулся, шесть предупреждений остались, и причина записана в шапке файла:
`#cfg` на импорт не вешается, `nova:allow unused-import` не действует (это
предупреждение чекера, а люк подавления достаёт только до линт-кодов).
Маркер `[M-unused-import-across-cfg-split]`.

## Чего эти пробы НЕ доказывают

Что запись автозапуска действительно появляется в `…\CurrentVersion\Run` и
действительно запускает бэкенд при входе. Это требует записи в ключ автозапуска
владельца и перезахода в систему — **вопрос владельцу**, не решение окна. Проверено
всё, что можно проверить, не меняя его машину.

И ничего не проверено на Linux: там нет ни машины, ни прогона. Написана только форма,
и её ошибка (снятый импорт) была поймана здесь случайно — это цена, а не гарантия.
