# Запись, объявленная ВНЕ входного модуля, не собирается вовсе

**Дата:** 2026-09-14, 00:18–00:20. **Класс:** кодогенератор ищет схему записи по
имени и не находит её для типа из другого модуля пакета.

## Репро

```sh
cd probes/record-literal-not-in-schemas
../../nova.sh build src/main.nv
```

```
error: codegen error: anonymous record literal: expected struct 'Ask' not in record_schemas
```

Два файла: `src/right.nv` объявляет `export type Ask value { path str, depth int }` и
конструктор `Ask.of(path, depth) -> Ask => { path, depth }`; `src/main.nv` его
импортирует и зовёт. `nova check` проходит, падает эмиссия.

**Форма конструктора — та, которую дерево считает РАБОЧЕЙ.** `src/accounts/discover.nv`
пишет прямо: «Constructors, because a bare record literal in a `return` is refused by
codegen. In tail position the return type names it; behind `return` it does not, so
the literal gets a home.» Здесь литерал стоит в хвостовой позиции и возвращаемый тип
его называет — и всё равно отказ. То есть записанное в дереве правило обхода эту
форму не покрывает.

## ЧЕГО ЭТА ПРОБА НЕ ДОКАЗЫВАЕТ, и это главное

Она писалась, чтобы воспроизвести ДРУГОЙ дефект — тот, что остановил сборку роутера
`claude-limits` (`conflicting types for nova_fn_8handlers7refresh9parse_ask`,
`no member named 'tag' in struct NovaValue_TokenState`). **Она его не воспроизводит.**

Установлено контролем: я убрал второй модуль ЦЕЛИКОМ, так что столкновение имён стало
невозможным, — и получил ту же самую ошибку. Значит причина не в столкновении.

Перед этим я поставил более слабый контроль (переименовать один из двух одноимённых
типов) и он тоже не помог — ошибка поехала за новым именем. Уже он говорил, что
гипотеза не та, но окончательно её снял только контроль с удалением модуля.

**Без контроля я завёл бы неверную причину с правдоподобным репро при ней**, а это
хуже, чем не заводить ничего: следующий читатель починил бы названное и удивился, что
предмет не двинулся.

## Настоящая находка ждёт своего репро

Столкновение имён в `claude-limits` остаётся фактом и воспроизводится на самом
продукте:

```sh
./nova.sh test src/server/ --filter app
```

Девять имён делятся между модулями `src/server/handlers/`: `Ask` в четырёх,
`parse_ask` в четырёх, `run` в семи, `body_str` в четырёх. Каждый хендлер писался и
проверялся в одиночку, и до сборки роутера ни один CU не держал двух сразу. Минимальное
репро для этого случая ещё не написано — и пока его нет, честно сказать «есть отказ на
продукте», а не «есть репро».
