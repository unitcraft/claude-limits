# Находка: обновление `value`-записи через spread даёт C, который не компилируется

**Дата:** 2026-09-08. **Нашлось** дважды за один день, разными путями:

1. спайк T0.2 — `req = req.header(...)` на билдере `mut @ -> @`;
2. задача T1.1 — `x = { ...x, поле: v }` на `value`-записи.

**Класс — один:** сгенерированный C присваивает УКАЗАТЕЛЬ в значение. Фронтенд
принимает обе формы: Nova читается нормально, отказ приходит от clang и назван его
именами, а не нашими.

## Проба (двадцать строк, без зависимостей)

```sh
cd probes/value-record-spread
../../nova.sh build src/main.nv
```

```
main.c:5467:20: error: indirection requires pointer operand
                       ('NovaValue_Box' (aka 'struct NovaValue_Box') invalid)
 5467 |     *_nv_tmp_478 = *x;
main.c:5469:7:  error: assigning to 'NovaValue_Box' from incompatible type
                       'NovaValue_Box *'; dereference with *
 5469 |     x = _nv_tmp_478;
2 errors generated.
```

## Контроль — одна строка

Закомментировать `x = { ...x, b: 2 }` — и тот же файл собирается и печатает:

```
built: main.exe (5.31s)
spread: a=one b=1
field assignment: a=two b=20
```

То есть виновата ровно одна форма, а не запись, не тип и не сборка. Рабочая форма —
присваивание поля на `mut`-локали (`y.b = 20`), она в файле рядом и работает.

**Проба намеренно оставлена КРАСНОЙ.** Починится — она позеленеет сама и об этом
скажет; закомментированная строка была бы пробой, которая ничего не проверяет.

## Что задето в плане 01

`src/storage/paths.nv`: поля `PathsInput` объявлены обычными, а не `ro`, и тесты
собирают запись присваиванием полей. С работающим spread запись была бы `ro`
целиком — это не обход ради красоты, а вынужденная потеря неизменяемости во входной
записи.

## Границы

- Замерено на Windows, clang. На других платформах и тулчейнах не проверялось.
- Не проверялось, задета ли форма `{ ...a }` без изменения полей и spread в позиции
  аргумента: пробе хватило одной формы, чтобы стать воспроизводимой.
- Номер реестра НЕ взят: номера выдаёт интегратор, у окна сейчас есть №1033 под
  другой дефект. Эту находку надо предъявить отдельно.

## Строка реестра: №1036

Заведена интегратором в `nova/docs/plans/221.1-bug-sweep.md` 2026-09-08 по тексту этой пробы: «обновление value-записи через spread эмитит C, присваивающий указатель в значение».

Номер НЕ выбран здесь и не может быть: счёт ведёт ОДИН человек, иначе две головы ведут два счёта и они расходятся. Здесь разошлись в ОБЕ стороны сразу: я считала своей чужую строку №1040 и НЕ считала своими три настоящие, включая эту.
