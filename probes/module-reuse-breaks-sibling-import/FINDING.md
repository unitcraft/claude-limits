# Голый импорт соседа внутри модуля резолвится от каталога ТОГО, КТО ИМПОРТИРУЕТ

**Приоритет:** К1 (модуль с голыми импортами соседей нельзя переиспользовать из
другого каталога вообще; ошибка указывает на файл, в котором нет ни одной ошибки).
**Найдено:** 2026-09-08, при раскладке `server/handlers/` (claude-limits, T2.12).
**Номер реестра:** №TBD.

## Класс

`import leaf` внутри `lib_a/uses_bare.nv` резолвится **не** от каталога
`uses_bare.nv`, а от каталога того файла, который импортировал `uses_bare`. Пока
потребитель лежит в том же каталоге, всё сходится и дефекта не видно. Первый же
потребитель из другого каталога получает:

```
cannot find module 'leaf'
    searched:
       src/lib_b\leaf (single-file or folder)
       D:\...\leaf   (single-file or folder)
```

`leaf` лежит в `src/lib_a/`. Там его никто не искал.

**Практическое следствие:** модуль, который импортирует соседей голым именем, годен
только внутри своего каталога. Общая библиотека, разложенная по каталогам, собирается
до первой попытки её переиспользовать — и ошибка при этом называет ЧУЖОЙ файл
(`consumer_bad.nv`), в котором ничего не сломано.

**Обход:** писать импорты с префиксом пакета —
`import <пакет>.lib_a.leaf.{value}`. Тогда модуль переносим. Применено в
`src/server/{errors,dto,routes}.nv` claude-limits тем же слиянием, с причиной в
шапке каждого файла.

## Проба

```
cd <repos>/claude-limits/probes/module-reuse-breaks-sibling-import
../../nova.sh check src/lib_a/peer_ok.nv        # CONTROL 1 -> ok
../../nova.sh check src/lib_b/consumer_good.nv  # CONTROL 2 -> ok
../../nova.sh check src/lib_b/consumer_bad.nv   # -> FAIL
```

| файл | потребитель | как импортирует импортируемый модуль | результат |
|---|---|---|---|
| `lib_a/peer_ok.nv` | тот же каталог | голым именем | **ok** |
| `lib_b/consumer_good.nv` | другой каталог | с префиксом пакета | **ok** |
| `lib_b/consumer_bad.nv` | другой каталог | голым именем | **FAIL** |

Три случая отличаются друг от друга ровно одним признаком каждый, поэтому вывод —
про сочетание «другой каталог + голый импорт внутри», а не про «импорты вообще».

## Поправка к тому, что я думал раньше

До этой пробы я считал (и записал в шапках нескольких файлов, и вынес из-за этого
`src/window.nv` в корень исходников), что **кросс-каталожные импорты в Nova просто не
резолвятся**. Это неверно: резолвятся, форма — `<пакет>.<каталог>.<модуль>`.
Проверено на глубине 1 и 2. Голый вид не работает никогда, кроме соседей по каталогу,
и именно его я пробовал.

Замер, на котором построена поправка:

```
src/server/probe_x.nv, module server.probe_x
  import model.store.{Snapshot}                  -> cannot find module 'model.store'
  import claude_limits.model.store.{Snapshot}    -> ok
```

## Чего проба НЕ утверждает

Не проверено, как это ведёт себя при импорте из ДРУГОГО пакета (все три случая —
внутри одного). Второй путь в списке `searched` (`D:\...\leaf`) выглядит как корень
рабочего каталога, а не корень пакета, и с `[lib] src = "src"` не совпадает ни для
какого пакета; отдельная ли это ошибка — вопрос к тому, кто владеет резолвером.
