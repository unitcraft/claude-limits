# Обработчик эффекта по умолчанию собирается GC, и следующий вызов прыгает в мусор

**Замер 2026-09-30, 18:20–18:35.** Бинарь `nova-integ` на `8900d9a61`, Windows 11,
Boehm GC. Номер реестра — `№TBD` (выдаёт интегратор). Найдено на падении
`claude-limits --serve` с конфигом `[server] port = …` без `[[folders]]`.

## Как запускать

Переименовать `nova.toml.txt` → `nova.toml`, `e1_default_handler_gc.nv.txt` →
`e1_default_handler_gc.nv`, затем:

```
nova build e1_default_handler_gc.nv -o e1.exe && ./e1.exe
```

## Замер

| проба | что | исход, 10 запусков |
|---|---|---|
| `e1_default_handler_gc` | `Uuid.v7()` (ставит обработчик `Random` по умолчанию) → ~800 000 мелких строк, отброшенных → `Uuid.v7()` снова | **10/10 `Segmentation fault`** |
| то же с `GC_DONT_GC=1` | сборщик выключен | **0/10** |
| `e2_control_installed_after` | e1 без первого вызова: обработчик ставится ПОСЛЕ нагрузки | **0/10**, `e2 ok 800000 true` |

## Причина — прочитана в выпущенном C

Для эффекта с обработчиком по умолчанию кодоген выпускает потоколокальный слот и
ленивую установку при первом вызове:

```c
__declspec(thread) NovaVtable_Random* _nova_handler_Random = NULL;
static inline uint64_t Nova_Random_u64(void) {
    if (!_nova_handler_Random) { _nova_handler_Random = nova_fn_7prelude7effects11real_random(); }
    ...
    return _nova_handler_Random->u64(_nova_handler_Random->ctx);
}
```

`real_random()` выделяет vtable и ctx через `nova_alloc`, то есть в куче GC. Единственная
ссылка на них — потоколокальный слот. Потоколокальная память корнем для Boehm не
является, а рантайм к тому же ставит `GC_set_no_dls(1)` и регистрирует корни руками
(`nova_gc_add_root`, `alloc_boehm.c:297-303`, «module-level lazy-static»). Слоты
`_nova_handler_*` не регистрирует никто. Первая же сборка освобождает vtable, блок
уходит под новые объекты, и вызов идёт через чужие байты.

**Как это выглядело в продукте** (`NOVA_DIAG_SEGV=1`, тест `src/server/start_test`):
`run_api_q → request_id_of → Uuid.v7 → Nova_Random_u64` → прыжок по адресу `0x1`. В
релизной сборке `--serve` в RCX и RAX лежали байты `# claude` и `toml —`, то есть
текст отрендеренного TOML занял освобождённый vtable. Без `[[folders]]` раскладка кучи
такова, что блок переиспользуется до первого запроса; с папкой — позже. Отсюда 5/5
падений на одном конфиге и 0/5 на другом, а любая правка кода двигает картину: это не
ось, а время.

## Класс

В одном выпущенном C (`src_server_start_test.c`) так устанавливаются по умолчанию
семь эффектов: `Fs`, `Io`, `Log`, `Net`, `Os`, `Random`, `Time`. Уязвима **любая**
программа, которая сначала вызывает эффект без `with`, потом делает достаточно
выделений, чтобы прошла сборка, а потом зовёт тот же эффект снова, — то есть почти
всякий долгоживущий процесс. На M:N каждый поток-воркер ставит свой слот лениво.

Направление починки (не проверено): выделять vtable и ctx обработчиков по умолчанию
через `nova_alloc_uncollectable`, либо регистрировать слоты как корни.
