# Находка: `[ffi]`-шим ТРАНЗИТИВНОЙ зависимости не собирается — линковка падает

**Дата:** 2026-09-08. **Нашлось** при сборке спайка T0.2 (план 01 Ф.0 п.2), когда
пакет с единственной зависимостью `http` впервые дошёл до разжатия ответа.

**Класс:** не «C-конвейер сломан» и не «мой граф слишком глубокий» — ровно одно:
пакет, объявляющий `[ffi] c_shims`, получает свой шим скомпилированным, когда он
**прямая** зависимость, и НЕ получает, когда он **транзитивная**.

## Что видно

Сборка `spikes/https-usage` (зависимость: только `http`; `compress` приезжает через
`http`) проходит фронтенд, генерирует C и падает на линковке:

```
lld-link: error: undefined symbol: compress_brotli_dec_new
lld-link: error: undefined symbol: compress_brotli_dec_pull
lld-link: error: undefined symbol: compress_brotli_dec_done
lld-link: error: undefined symbol: compress_brotli_dec_needs_input
clang: error: linker command failed with exit code 1
```

Все четыре — функции из `nova-compress/native/compress_shim.c`. Сам вендоренный
`brotlidec.lib` в кэше ЕСТЬ:

```
~/.nova/git/co/nova-compress-49f47e4da8980809/<rev>/native/brotli/lib/brotlidec.lib
```

То есть собралась вендоренная библиотека, а шим — нет.

## Изоляция (этот каталог)

Пакет `probe_brotli_shim_link` зависит от `compress` **напрямую** и зовёт
`brotli_decode`. Из картины убраны и `http`, и `tls`.

```sh
cd probes/brotli-shim-link
../../nova.sh build src/main.nv     # built: main.exe (18.29s)
./main.exe
```

```
inflate: refused the input, which is fine -- it LINKED
brotli: refused the input, which is fine -- it LINKED
```

**Линкуется и работает.** В файле намеренно две половины: `inflate` — чистая Nova
без FFI (контроль, обязан линковаться всегда), `brotli_decode` — через шим. Вход —
заведомый мусор: проба про ЛИНКОВКУ, а не про декодирование, и декодер, вернувший
ошибку, уже доказал, что символ разрешился.

## Контроль, что дело не в среде

Заведомо рабочий соседний спайк `spikes/polaris-sse` пересобран тем же
`nova.sh` в тот же час: `built: main.exe (24.10s)`. Он тянет `compress` тем же
транзитивным путём, но это СЕРВЕР — клиентского разжатия он не достигает, и DCE
выбрасывает вызовы брotli. Поэтому он и не падал: отсутствие символов видно только
у того, кто до них доходит.

## Вторая проба, и она сильнее первой

`probes/http-client-link/` — четырнадцать строк Nova, единственная зависимость
`http`, простейший GET без авторизации, заголовков и JSON, никуда не отправляемый:

```sh
cd probes/http-client-link
../../nova.sh build src/main.nv
```

```
lld-link: error: undefined symbol: compress_brotli_dec_new
lld-link: error: undefined symbol: compress_brotli_dec_needs_input
clang: error: linker command failed with exit code 1
```

**То есть падает не «спайк с его импортами», а ЛЮБОЙ пользователь HTTP-клиента.**
В обвинение спайку теперь нечего поставить: у пробы нет ни файловой системы, ни
JSON, ни токена.

`HttpClient.builder().no_decompress()` **НЕ помогает** — проверено сборкой: флаг
разжатия рантаймовый, код пути компилируется всё равно, и ссылка на
`compress_brotli_dec_*` остаётся. Обхода на уровне вызывающего кода нет.

## Чего проба НЕ утверждает

- Что виноват именно `compress`. `tls` — тоже транзитивный через `http`, тоже с
  `[ffi]`, и его символы в том же прогоне разрешились. Значит правило «шим
  транзитивной зависимости теряется» в такой формулировке **неверно**, и настоящее
  различие между `tls` и `compress` этой пробой НЕ найдено. Кто чинит — тому и
  измерять; здесь зафиксировано наблюдаемое, а не диагноз.
- Что это дефект компилятора, а не пакета. Возможны обе стороны.

## Что это значит для плана 01

**Это блокер, а не неудобство.** Приложение — HTTP-клиент: опрос эндпоинта есть
весь смысл Ф.1. Пока это не починено, на этой машине не собирается НИ ОДИН пакет,
зовущий клиент, — значит не собираются ни спайк T0.2, ни `usage/`, ни `--once`.
Обхода на стороне вызывающего кода нет: `no_decompress()` проверен и не помогает.

Что остаётся возможным без починки: всё, что не трогает клиент, — `config.nv`,
`storage/paths.nv`, страница (она уже сделана), спайк времени T0.3.

**Строка реестра `221.1` не заведена:** номера выдаёт интегратор, а это окно
работает в границах плана 01. Находка передана владельцу и интегратору отдельно.

## Строка реестра: №1033

Заведена интегратором в `nova/docs/plans/221.1-bug-sweep.md` 2026-09-08 по тексту этой пробы: «ни один пакет, зовущий HTTP-клиент, не линкуется: четыре неразрешённых символа шима».

Номер НЕ выбран здесь и не может быть: счёт ведёт ОДИН человек, иначе две головы ведут два счёта и они расходятся. Здесь разошлись в ОБЕ стороны сразу: я считала своей чужую строку №1040 и НЕ считала своими три настоящие, включая эту.
