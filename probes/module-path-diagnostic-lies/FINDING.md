# `E_D78_MODULE_PATH_MISMATCH` называет ожидаемой ту самую строку, которую отвергает

**Приоритет:** К3 (диагностика уводит в сторону; сборка не ломается, ломается человек
или агент, который делает ровно то, что сказано).
**Найдено:** 2026-09-08, при раскладке `server/handlers/` (claude-limits, T2.12).
**Номер реестра:** №TBD.

## Класс

Ошибка перечисляет ТРИ «ожидаемых» формы имени модуля, а принимает ОДНУ. Хуже: в
типичном случае одна из отвергнутых форм печатается **посимвольно равной** тому, что
объявлено, — прямо в соседней строке того же сообщения:

```
declares `module_path_diagnostic_lies.sub.named_but_refused`
expected (rev-1 legacy):    `module_path_diagnostic_lies.sub.named_but_refused`
```

Читатель обращается к этому сообщению именно тогда, когда правила не знает. Оно
называет ему форму, которая не работает, — и он пробует её, получает то же
сообщение, и цикл замыкается. Слово «expected» означает «принимается»; здесь оно
означает «когда-то называлось так».

Действующее правило, выведенное пробой: **модуль = `<родительский каталог>.<имя
файла>`**, причём каталог-корень исходников читается как имя пакета. Всё остальное из
списка не принимается ни на какой глубине — проверено на 0, 1 и 2.

## Проба

```
cd <repos>/claude-limits/probes/module-path-diagnostic-lies
../../nova.sh check src/sub/ok_form.nv            # CONTROL -> ok
../../nova.sh check src/sub/named_but_refused.nv  # -> FAIL, см. выше
```

| файл | форма | результат |
|---|---|---|
| `src/sub/ok_form.nv` | `sub.ok_form` (rev-3 `parent.X`) | **ok** |
| `src/sub/named_but_refused.nv` | `<пакет>.sub.named_but_refused` (rev-1, названа «expected») | **FAIL** |

Проверено также на настоящем дереве claude-limits: `claude_limits.server.probe_depth1`
на глубине 1 отвергается, `server.probe_depth1` принимается. То есть дело не в
глубине — форма rev-1 не принимается нигде.

## Поправка к первой редакции этого файла, того же дня

Здесь стояло второе наблюдение: будто модуль из подкаталога **не может** импортировать
модуль из соседнего каталога, потому что в списке `searched:` нет `src/`. **Это было
неверно, и неверно оно было по той же причине, по какой написан весь этот файл:** я
взял форму имени, не проверив её. Кросс-каталожный импорт резолвится — формой
`<пакет>.<каталог>.<модуль>`:

```
src/server/probe_x.nv, module server.probe_x
  import model.store.{Snapshot}                  -> cannot find module 'model.store'
  import claude_limits.model.store.{Snapshot}    -> ok
```

Что там ДЕЙСТВИТЕЛЬНО сломано — оказалось другим и уже отдельно изолировано:
голый импорт соседа ВНУТРИ модуля резолвится от каталога того, кто импортирует этот
модуль, а не от самого модуля. Проба с тремя контролями —
[probes/module-reuse-breaks-sibling-import/](../module-reuse-breaks-sibling-import/).

Находка этого файла — про диагностику — стоит как стояла: она проверена пробой и
контролем и от поправки не зависит.

## Чего проба НЕ утверждает

Не проверено, ПОЧЕМУ форма rev-1 перечислена: возможно, она принималась раньше и
строку забыли убрать, возможно — принимается при какой-то настройке, которой в этом
пакете нет. Проба говорит только одно и говорит это твёрдо: в том виде, в каком
сообщение читает человек, оно называет ожидаемым то, что тут же отвергает.
