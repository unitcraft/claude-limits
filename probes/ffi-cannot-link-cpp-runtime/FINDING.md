# Пакет с C++-библиотекой не собирается на Linux: связать `libstdc++` манифестом нечем

**Найдено:** 2026-09-09 02:47Z, прогоном `pkg-gate` на Linux.
**Приоритет:** высокий — блокирует CI пакета целиком; на Windows пакет работает.
**Дом дефекта:** компилятор Nova (манифест `[ffi]` и драйвер линковки), не пакет.
**Статус:** воспроизведено на CI, причина названа, обхода в нынешнем манифесте НЕТ.

## Что произошло

Гейт дошёл до шага 14 из 14 — сборка DuckDB, сверка манифеста, стражи, сверка тега
прошли — и упал на линковке теста:

```
ub_duckdb_main_capi.cpp:(.text+0x292): undefined reference to `operator delete(void*)'
ub_duckdb_main_capi.cpp:(.text+0x33e): undefined reference to `operator new(unsigned long)'
ub_duckdb_main_capi.cpp:(.text+0x5ce): undefined reference to `std::__throw_logic_error(char const*)'
```

DuckDB написан на C++. На Linux при линковке C-драйвером нужно явно подать
`-lstdc++`; на Windows статические библиотеки MSVC тянут свой рантайм сами, поэтому
там пакет собирается и проходит 21/21.

## Почему обойти нельзя

**`[ffi] libs` — один плоский список, разделения по платформам нет.** У парсера
манифеста пять ключей (`c_shims`, `include_dirs`, `lib_dirs`, `libs`,
`vendor_src_dirs`), ни один не условный — `manifest.rs:600-604`.

**Вписать `stdc++` в `libs` нельзя:** `first_missing_ffi_lib`
(`link_prep.rs:60-73`) требует, чтобы КАЖДАЯ запись нашлась файлом в `lib_dirs`. На
Windows `stdc++.lib` не существует, значит весь пакет уйдёт в
`SkipReason::FfiLibNotFound` — то есть тесты станут молча пропускаться. Зелёный,
который ничего не измеряет, хуже красного.

**Шимом на C++ тоже нельзя:** грепом по `link_prep.rs`, `manifest.rs` и `nova-cli`
слов `cpp`, `cxx`, `c++`, `stdc++` — НОЛЬ вхождений. Компилятор о существовании C++
не знает: ни компиляции `.cpp` в `c_shims`, ни выбора драйвера линковки.

**Почему это всплыло только сейчас:** остальные пакеты вендорят C — mbedTLS в
`nova-tls`, brotli в `nova-compress`. `nova-duckdb` первый, кому нужен C++-рантайм.

## Что нужно от компилятора (одно из двух)

1. **Платформенный список библиотек** — `[ffi] libs` с условием по ОС. Это же нужно
   было сегодня для `jemalloc`, который Linux собирает, а Windows нет; тогда я
   выключил его флагом, и это стоило Linux более быстрого аллокатора
   (`[M-ffi-libs-per-platform]`). Второй носитель за ночь, и этот уже не обходится.
2. **Знание о C++ в драйвере линковки** — если среди `c_shims` или влинкованных
   архивов есть C++, линковать `clang++`/`-lstdc++`. Уже, ради чего: любой
   вендоринг C++-библиотеки упрётся в то же самое.

Первое шире и закрывает оба носителя; второе точнее для этого случая.

## Чего я НЕ стал делать, и почему это записано

Подложить пустой `stdc++.lib` на Windows, чтобы проверка наличия прошла. Это
удовлетворило бы стража, ничего не починив, — ровно тот класс, который я весь вечер
вычищаю из этого дерева.

Оставить гейт зелёным, пропустив шаг тестов на Linux. Тогда гейт сообщал бы об
исправности, которой нет.
