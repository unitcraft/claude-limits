# Вызов свободной функции берёт соглашение о `mut`-параметре у ОДНОИМЁННОЙ функции другого модуля

**Замер 2026-10-02 06:31.** Реестр 221.1 — `№TBD` (номер даёт интегратор). Класс: К1
(молча неверный код), семья №154/№1390 — одноимённые свободные функции разных модулей в одной

`D:/Sources/nv-lang/nova` (сборка 06:27, HEAD тогда `564bc9665`); опубликованный `main` —

## Что происходит

Модуль `backups` вызывает СВОЮ `stamp(ms int) -> str`. В единице есть ещё
`respond.stamp(mut r Rec) -> Rec` — та же арность, параметр `mut`. Сгенерированный C зовёт
правильную функцию, но передаёт ей АДРЕС аргумента:

```c
static nova_str nova_fn_7backups5stamp(nova_int ms) {          /* верная функция */
...
nova_fn_7backups5stamp((&(ms)))                                 /* &ms вместо ms */
```

Компилятор C это принимает: в `ms` приходит адрес стека, функция считает по нему.

| проба | ожидание | получено |
|---|---|---|
| `q_mut_param_by_name` | `backups.named  x-1790911579` | **`x-2196359668`** — от адреса, меняется от запуска к запуску |
| то же, `respond.stamp` переименована в `bump` (КОНТРОЛЬ) | `x-1790911579` | `x-1790911579`; в C — `stamp(ms)` |

## Где ударило (claude-limits)

`storage/backup.nv` `stamp(ms)` рядом с `server/static.nv` `stamp(mut resp ServerResponse)` и
`server/routes.nv` `stamp(mut resp, request_id)`. В тестовой единице хранилища имена бэкапов
верны; в бинаре бэкап перед миграцией в 03:18 UTC назван `claude-limits-20340304-0656.duckdb`,
следующие — `…-20420605-2047`, `…-20581216-1252`. Имена не сортируются по времени, поэтому
`weekly_due` судит наугад, а `backups_keep` может удалить самую свежую копию. Обход в
claude-limits — переименование (`backup_stamp`), его держит `backup_name_linked_test`
(красный до переименования: `…-20150831-1621`, зелёный после).

## Как запускать

Каталог-пакет: `nova.toml.txt` → `nova.toml`, `respond/respond.nv.txt` → `respond/respond.nv`,
`backups/backups.nv.txt` → `backups/backups.nv`, `q_mut_param_by_name.nv.txt` →
`q_mut_param_by_name.nv`; `nova build q_mut_param_by_name.nv -o q.exe --keep-artifacts`,
запустить, в C найти `backups5stamp((&`. Имена модулей не `a`/`b`: модуль `a` сталкивается с
`a.compare` из std (`E7401 no function compare in module a`, отдельный известный класс).

## Чем это не является

Не «выбрана чужая функция» (символ верный) и не №1390 в чистом виде (там сборка отказывает с
`E_CODEGEN_TYPE_UNKNOWN`; здесь она проходит). Отказ №1390 виден рядом: вызов того же `stamp`
из ТРЕТЬЕГО модуля, где тип результата не выводится, сборка отвергает — а вызов изнутри
модуля-владельца проходит и молча передаёт адрес.
