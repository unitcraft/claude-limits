## Факты, каждый — замер

1. **Линковка — обходом №1033.** С одной зависимостью `http` сборка падает на пяти
   `compress_brotli_dec_*`, затем на `tls_*`: шим `[ffi]` транзитивной зависимости не
   собирается (`probes/brotli-shim-link/`). С `compress` и `tls` ПРЯМЫМИ зависимостями —
   собирается. Спайку добавлен `with Http = real_http()` (писался, пока `real_http` не
   собирался).
2. **Сверка с эталоном (14:02:53, учётка `nv-lang`).** Спайк: session 21, weekly_all 20,
   weekly_scoped 0; сбросы 13:30Z и 18:00Z. Эталон: session 21 %, weekly_all 20 %,
   Fable 0 %; сбросы 16:30 и 21:00 по Москве — те же моменты.
3. **Откуда корни.** `tls_cfg_verify_system` в `nova-tls` (коммит тега `7fad866`,
   `native/tls_c_shim.c:593`) грузит ВШИТЫЙ список Mozilla (`tls_mozilla_roots.h`,
   150 сертификатов), а не хранилище ОС. Имя режима обещает «системные» — поведение иное.
4. **Перехват.** Соединение, которое перехватил Касперский, подписано его корнем из
   хранилища Windows; вшитый список его не знает — отказ «X509 - Certificate verification
   failed» (13:01). Python доверяет хранилищу Windows и такие соединения принимает.

## Что из этого следует

- Живой опрос из claude-limits **работает** (`--serve`, 2026-09-30 14:00: учётка `ok`,
  три окна) — но на машине с перехватывающим антивирусом часть раундов будет отказом
  проверки. Учётка тогда уходит в `unknown` с последними данными и текстом «network error»,
  следующий раунд обычно проходит.
- Лечение то же, что было названо: `verify_system` должен брать корни из хранилища ОС
  (вшитый список — запасной). Это уже не «иначе не работает», а «иначе прерывисто». Вопрос 9
  плана 01.5 поправлен соответственно.
