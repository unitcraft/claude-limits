# Вердикт спайка T0.2 — HTTPS к эндпоинту использования

**Замер 2026-09-30 12:55–13:05**, Windows 11, бинарь `nova-integ` 10:55, окно claude-limits.
Вердикта не было с 2026-09-09: спайк не линковался (реестр №1033).

## Ответ одной строкой

**Соединение есть, проверки сертификата нет — на ЭТОЙ машине.** Спайк собирается, доходит до
`api.anthropic.com` и падает на TLS: «certificate invalid: X509 - Certificate verification
failed». Причина — не пакет и не сеть: TLS на машине перехватывает антивирус, и
`nova-tls` не доверяет его корню, потому что берёт корни не из хранилища ОС.

## Три факта, каждый — замер

1. **Линковка — обходом №1033.** С одной зависимостью `http` сборка падает на пяти
   `compress_brotli_dec_*`, затем на `tls_*`: шим `[ffi]` транзитивной зависимости не
   собирается (`probes/brotli-shim-link/`). С `compress` и `tls` ПРЯМЫМИ зависимостями —
   `built: https-spike.exe (64.00s)`. Сам спайк не имел обработчика `Http` (писался, пока
   `real_http` не собирался) — добавлен `with Http = real_http()` в `main`.
2. **Откуда корни.** `tls_cfg_verify_system` в `nova-tls` (коммит тега `7fad866`,
   `native/tls_c_shim.c:593`) грузит ВШИТЫЙ список Mozilla (`tls_mozilla_roots.h`,
   150 сертификатов), а не хранилище ОС. Имя режима обещает «системные» — поведение иное.
3. **Что на проводе.** Рукопожатие из Python к `api.anthropic.com:443` показывает издателя
   `Kaspersky Anti-Virus Personal Root Certificate` (AO Kaspersky Lab), TLS 1.3: антивирус
   подменяет сертификаты и ставит свой корень в хранилище Windows. Эталон
   `scripts/claude_limits.py --once --no-auto-refresh` по той же учётке отвечает (session
   12 %, weekly_all 18 %, Fable 0 %) — он доверяет хранилищу Windows. Токен и сеть в порядке.

## Что из этого следует для приложения

- Живой опрос из claude-limits на машине владельца **невозможен**, пока `nova-tls` не берёт
  корни из хранилища ОС (Windows: `CertOpenSystemStore("ROOT")`; Linux: системный бандл) —
  хотя бы в дополнение к вшитому списку. Это поведение браузера и Python; вшитый список
  ломается ровно у пользователя с корпоративным прокси или антивирусом.
- Второй путь — не лечить: приложение с перехватом TLS не работает, и это говорится текстом
  ошибки. Оно честно, но у владельца продукт тогда не работает вовсе.
- Решение — в открытых вопросах плана 01.5 (вопрос 9).

## Не проверено

- Linux и macOS: не было машины.
- Сверка полей `kind/percent/resets_at` с эталоном — до неё запрос не дошёл.
- `no_decompress()` в спайке оставлен: при прямой `compress` он больше не нужен для
  линковки, но спайк отвечает на вопрос о корнях, а не о сжатии.
