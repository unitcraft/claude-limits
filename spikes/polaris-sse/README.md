# Spike T0.1 — Polaris from a clean package

**Статус: написан, НЕ СОБРАН.** Ждёт слота на машине: во время написания её держал
гейт интегратора, и по норме своих сборок в это время не запускаю.

## Вопрос

План 01 Ф.0 п.1: может ли пакет, у которого из зависимостей только `polaris`,
отдавать встроенную страницу, JSON и SSE, **кадры которого приходят из канала от
другого файбера**, при том что `serve_router` живёт в `spawn` под `supervised`, а не
владеет `main`?

Последняя часть — главная. Оба примера Polaris ставят accept-loop прямо в `main`
(«main IS the accept loop»), а приложению так нельзя: при `--widget` в `main` крутится
цикл событий SDL, значит сервер обязан жить в отдельном файбере (план 01 §3.1). Этот
спайк — первое место, где такая форма проверяется.

## Что внутри

| файл | что проверяет |
|---|---|
| `main.nv` | `Router` с четырьмя маршрутами; `embed_dir("web")` + `serve_path`; SSE через `stream_body`, читающий `ChanRx[str]`; продюсер и сервер — два `spawn` под одним `supervised` |
| `web/index.html` | страница внутри бинаря; на ней `EventSource` показывает пришедшие кадры |
| `nova.toml` | отдельный пакет: зависимость `polaris` по git-диапазону `0.1`, как у приложения |

## Как прогнать (когда машина свободна)

```sh
cd spikes/polaris-sse
../../nova.sh build --mode release main.nv -o target/spike.exe
./target/spike.exe &
curl -s http://127.0.0.1:7391/ | head -5          # страница из бинаря
curl -s http://127.0.0.1:7391/api/snapshot        # JSON
curl -sN http://127.0.0.1:7391/api/events         # три кадра tick, затем done
```

## Приёмка (карточка T0.1)

- `curl -s /` отдаёт страницу;
- `curl -sN /api/events` получает **три** события, присланные в `Chan` из другого
  файбера, и затем `done`;
- сборка на Windows (Linux — если будет машина);
- размер бинаря записан.

## Чего спайк не проверяет

Правило `#thread_affine` для SDL (это спайк Ф.3), нагрузку и keep-alive, TLS,
несколько одновременных подписчиков SSE (фан-аут — задача `store` в Ф.2).
