# claude-limits 0.1.0

First release: a local backend with a browser page that shows how much of your
usage limits is left, on one page, for several accounts. Windows x64 only.

> **Read this first.** The usage endpoint this tool asks is **not documented** by
> Anthropic (or by Moonshot / OpenAI for the other two services). It can change or
> disappear without notice, and then the numbers go stale or the poll fails until the
> tool is updated. It reads the login files your own CLIs already keep and sends
> their tokens only to the service they belong to.

## What is in it

- **Claude, Kimi Code and Codex on one page** -- every login found in the folders you
  list, with the session and weekly windows and the time to reset.
- **History in an encrypted database** (DuckDB; the key is a file beside the
  settings, `claude-limits.key` -- keep it with the database or the history is unreadable); `export` writes CSV/JSON with addresses masked by default, `forget
  <email>` removes one account and its traces.
- **Forecast** -- an estimate at the observed pace, not a guarantee of exact usage.
  Needs at least `max(30 minutes, 5% of the window)` of observed history in the current window.
- **Live updates** via SSE (`/api/events`), with polling fallback when the stream is unavailable.
- **Settings** in a TOML file and on the page; changes are picked up without a restart.
- **Autostart** -- `--install-autostart` / `--uninstall-autostart`.
- **Log file** -- a rotating log for `--serve`.
- `--once` prints the table in the terminal without starting the server.

## What is not in it

- **Linux**: the database library cannot be linked by the Nova toolchain yet, so
  there is no Linux build.
- **The widget button** and the always-on-top widget window are out of this release.
- **Threshold notifications** are browser-only: the page shows a system notification when a window passes 70 % or 90 % (off by default; enable it and grant permission in Settings). There are no notifications outside the browser tab, and none from the tray.
- **Live stream limitations**: disconnected clients can remain in the SSE connection
  count for about 2–4.5 minutes. Shutdown by signal does not send a `bye` event;
  the page falls back to polling when the connection closes.

## Install

1. Download `claude-limits-0.1.0-windows-x64.zip` and `SHA256SUMS.txt` from the assets
   below, and check the sum (next section).
2. Unpack the zip anywhere. It holds `claude-limits.exe`, `README.md`, both licences
   and `claude-limits.example.toml`.
3. `claude-limits.exe --serve`, then open <http://127.0.0.1:7391>.

The first start finds the default logins (`~/.claude`, `~/.kimi-code`, `~/.codex`);
others go into the settings file -- see the README and the example config.

## Verify the download

PowerShell, in the folder with both files:

```powershell
(Get-FileHash .\claude-limits-0.1.0-windows-x64.zip -Algorithm SHA256).Hash.ToLower()
Get-Content .\SHA256SUMS.txt
```

The two hashes must be identical. (With Git Bash or Linux: `sha256sum -c SHA256SUMS.txt`.)
The checksum shows the file arrived intact; it is published next to the file, so it does
not prove who built it. The exe is not code-signed, so Windows SmartScreen may warn on
first start.

Check the version: `claude-limits.exe --version` prints `claude-limits 0.1.0`.
