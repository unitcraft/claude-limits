# T0.0 — каркас пакета

Сделано: пакет `claude_limits` собирается и тестируется. Манифест `nova.toml`
(`[[bin]]`, три зависимости диапазоном `0.1`, без `[lib]` — корень пакета и есть корень
исходников), обёртки `nova.sh` и `nova.ps1`, точка входа `bin/claude_limits.nv`, чистый
модуль `version.nv` с версией и тест-заглушка `version_test.nv` рядом с ним,
`fixtures/README.md`, `docs/reports/README.md`, `target/` в `.gitignore`.

Обёртки закоммичены, в отличие от соседних пакетов, которые их игнорируют: приёмка
каждой задачи запускает `./nova.sh`, и клон, который не может её прогнать, — тот же
дефект, что держал эталон `claude_limits.py` вне git.

Оба SKIP ожидаемы и не скрывают работы: спайк DuckDB не линкуется без своей библиотеки
(она не собрана, задача T0.5), а `version.nv` не имеет тест-блоков и `main` — его
покрывает `version_test`.

Обратная проба: в `version.nv` добавлена функция `probe_print()` с вызовом `println`
(то есть печать из библиотечного модуля) → `./nova.sh test .` покраснел двумя
CODEGEN-FAIL, `PASS: 0 FAIL: 2`, оба с `version.nv:29:5: error: undefined identifier
println`; проба снята → `PASS: 2 FAIL: 0`. Остатков пробы в дереве нет.

Отклонения от входов: два, оба по факту прогона.

1. **Команда приёмки: `./nova.sh test bin/` → `./nova.sh test .`** Карточка требовала
   тест-заглушку в `bin/`, но тест, импортирующий точку входа, втягивает `fn main` в свой
   compilation unit и падает (см. «Дефекты Nova»). Заглушка переехала к модулю, который
   покрывает, — `version_test.nv` рядом с `version.nv`, как велит канон Nova
   (`authoring-a-module` §5), — а команда приёмки указывает туда, где тест реально есть.
   Литеральная команда карточки сегодня даёт `PASS: 1 FAIL: 0` (компилируется только
   `bin/claude_limits`, тестов там нет), то есть проходит вхолостую. Карточка T0.0 в
   подплане 01.5 исправлена тем же коммитом.
2. **`version.nv` не был в дереве плана 01 §3.2.** Появился как место для версии: держать
   её в точке входа нельзя, потому что тест не может импортировать точку входа. Файл
   маленький и чистый; в §3.2 добавлен.

Открытые вопросы: бриф §7 требует ветку `task/<id>-<slug>` и слияние интегратором, а
фактическая практика репозитория — коммиты прямо в `main` (так лежат и коммиты
параллельной сессии, и оба моих). Работал в `main`; правило либо снять из брифа, либо
начать соблюдать — вопрос владельцу, где искал: бриф §7, `git log --oneline`.

Дефекты Nova: один, найден пробой, номер не мой.

**`println` не работает вне entry-модуля compilation unit: чекер принимает, кодоген
отказывает.** Класс: расхождение `check` и кодогена на `extern "nova"`-вариадиках
прелюдии за границей модуля. Репро (минимальный, два файла):

```
# version.nv (module claude_limits.version)
export fn version_line() -> str => "claude-limits 0.0.0"
export fn probe_print() -> () { println(version_line()) }

$ ./nova.sh check version.nv
ok: version.nv
PASS: 1  FAIL: 0                      # чекер согласен

$ ./nova.sh test .
CODEGEN-FAIL   bin/claude_limits  # version.nv:29:5: error: undefined identifier `println`
CODEGEN-FAIL   version_test       # version.nv:29:5: error: undefined identifier `println`
PASS: 0  FAIL: 2                      # кодоген отказывает в КАЖДОМ юните, который импортирует модуль
```

Почему это дефект, а не норма: (а) чекер и кодоген расходятся на одном и том же файле —
`nova check` зелёный там, где сборка невозможна; (б) поведение нигде не описано —
грепом по `docs/dev/nv-coding-style.md`, `docs/guide/authoring-a-module.md`,
`docs/dev/module-conventions.md` про область видимости `println` нет ни строки; (в) сам
`nv-coding-style.md:535` показывает `fn Account @log(msg str) -> () => println(msg)` как
идиому, то есть документация обещает обратное. Живого примера печати из библиотечного
модуля в дереве нет: в `nova-polaris/src/net/serve.nv` оба `println` закомментированы
(строки 459, 486).

Цена для плана: любой библиотечный модуль, которому нужно печатать или логировать,
упирается в это. Затрагивает Ф.2 (сервер и поллеры захотят лог) — обход на сегодня
известен и применён: печать только в entry-модуле, наружу отдаются значения.
