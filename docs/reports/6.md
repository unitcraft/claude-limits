# 6 — кодировка журнала и падение при обновлении логина
Сделано:
(1) Журнал верен: приложение пишет UTF-8, перекодировки нет. «Р•РІРіРµРЅРёР№» — вид при чтении в PowerShell без `-Encoding utf8`. Менять код не пришлось; добавлен тест `a non-ASCII path reaches the file as UTF-8, byte for byte` (applog_test.nv).
(2) Падение с фиктивным `claude.cmd` не воспроизведено (см. ниже), поэтому «исправления падения» нет. Вместо него закрыта немая сторона: запуск Claude Code был «fire and forget», и при любом исходе (код 1, тишина, зависание, нет `claude`) в журнале стояло только «started». Теперь: (а) `claude.cmd` ищется в PATH до запуска, нет — строка `claude.cmd is not on PATH; the login stays expired` и запуска нет; (б) код выхода и невозможность запустить powershell дают свои строки; (в) на следующем круге вердикт по mtime файла (`launch_verdict`): не изменился за `timeout_sec`+15 с → `the credentials file did not change within N s; Claude Code failed, timed out or is not installed, and the login stays expired`, изменился → `was rewritten`. Состояние учётки остаётся `stale`, сервер продолжает опрос. Файлы: `src/accounts/claude_refresh.nv` (чистые функции), `src/claude_limits.nv` (`renew_claude`, `LoginTry`: поля `mtime_ms`, `judged`).

(3) Сегфолт `--serve` при длинном пути (письмо интегратора, воркер #7) — воспроизведён и обойдён. Воспроизведение на exe с ac813ab: CLAUDE_LIMITS_DATA так, чтобы путь журнала был 122, 125, 200 символов → exit 0xC0000005, «fiber stack overflow in slot 0 (access violation in fiber arena)», файл журнала не создан; 100–121 работают (порог плавает от сборки к сборке: в отладочной сборке 122–128 жили, 200 падал). Метки в отладочной сборке показали: падение внутри ПЕРВОГО файлового вызова рантайма по длинному пути (`Fs.mkdir`, а после замены на проверку — уже `metadata`), т.е. не в `scrub`/`format_line`/`rotate`. Минимальная программа с теми же вызовами (`env`, `dir_of`, `create_dir_all`, `metadata`, `File.append`, `record`) на путях до 200 символов не падает. Сервер с тем же длинным каталогом данных, но без журнала, живёт: база (DuckDB, свой файловый код) открывается, слушает. Рост NOVA_FIBER_STACK (до 256 МБ), NOVA_MAXPROCS=1, резерв стека exe 64 МБ — не помогают. Это дефект рантайма Nova (libuv-обёртка fs), не нашего кода; исправить его здесь нельзя. Обход: `applog.enable` возвращает `false` для пути длиннее `MAX_PATH_BYTES` = 100 байт (в байтах: кириллица считается по 2), файл не пишется, на консоль выходит строка `log file … is NOT written: the path is longer than 100 bytes …`. Дефект рантайма — строка в nova/docs/plans/221.1-bug-sweep.md не заведена (нет доступа на запись в nova; номер TBD, нужна интегратору).
