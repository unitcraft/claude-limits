Сделано: проведена portability-оценка неизменённого `v0.1.1` и его текущего build/release пути. Linux-сборка DuckDB существует в `nova-duckdb v0.2.2`, а pinned Nova содержит C++ driver для `nova test`; однако release-build путь приложения этим не покрыт. Подтверждённый Linux ELF, тестовая матрица и проверенный архив не получены. Публиковать Linux asset нельзя.

## Оценка переносимости и blocker

- В `nova-duckdb v0.2.2` есть Linux/macOS `scripts/build-duckdb.sh`; он строит DuckDB C++ и расширения `core_functions`/`icu`, выключает jemalloc для совпадения library manifest и требует CMake, Ninja и C++ toolchain. Linux исходная сборка native libraries сама по себе не доказывает сборку приложения.
- Исторический комментарий в `.github/workflows/ci.yml` говорит, что pinned Nova не умеет линковать C++ runtime. Это утверждение устарело: в точном Nova commit `5cdd2bc…` `[ffi] cxx = true` выбирает C++ driver в `compiler-codegen/src/test_runner.rs::build_command`; `nova build` вызывает тот же `compile_c_to_exe` с merged FFI config. Флаг, установленный в FFI config корневого пакета, сохраняется при merge.
- У `nova-duckdb v0.2.2` в `[ffi]` нет `cxx = true`, поэтому неизменённый tag не включает C++ driver при обычном build. Владелец разрешил одноразовый build-only overlay, добавляющий корневому package manifest `[ffi]\ncxx = true`, без изменения application `.nv` источников/tag и без включения overlay в дистрибутив. Добавлен PR-triggered GitHub Linux probe, который checkout-ит точный app SHA, pinned Nova и DuckDB, формирует overlay вне checkout и запускает настоящий Linux build/gates. Он ещё не запускался; технический blocker подтвердится или будет снят только этим runner.
- Linux release workflow отсутствует; нынешний `.github/workflows/release.yml` — Windows-only, использует Windows GC libs/PowerShell DuckDB builder/Windows ZIP. Локальная машина — Windows; WSL/host packages не устанавливали и не меняли. Настоящий Linux runner/container, Linux native tests, release build, `--version`, health, lifecycle/negative/restore probes, web/guard gates, ELF dependency inspection и чистый runtime unpack test в этой работе не запускались.
- Поэтому пока нет подтверждённого Linux compiler/runtime provenance/hash, ELF SHA-256, tested distro/libc, package hash, независимого review или безопасного основания для upload. Отдельный Linux SHA256 manifest и notes-section не создавались. `v0.1.1` tag, release body/assets, `v0.1.0` и application `.nv` source не изменялись.
