## 1. Что это за проект и где что лежит

`claude-limits` — один бинарь на Nova: бэкенд опрашивает эндпоинт использования Claude, хранит
историю в DuckDB, отдаёт страницу и JSON на `127.0.0.1:7391`; опционально виджет поверх окон на SDL3.
Публичное описание — [README.md](../README.md) (по-английски). Все проектные документы — по-русски.

## 2. Окружение и команды

### 2.1. Компилятор

Бинарь: `<repos>/nova/nova-cli/target/release/nova.exe` (на Linux без `.exe`). Ему нужны
переменные окружения, иначе `nova build` не находит std и рантайм. Каждый соседний пакет держит
обёртку `nova.sh`, у `claude-limits` она появляется задачей T0.0; до неё — руками:

```bash
M=<repos>/nova
export NOVA_STD_PATH="$M/std/src"
export NOVA_CG_INCLUDE="$M/compiler-codegen"
export NOVA_RT_DIR="$M/compiler-codegen/nova_rt"
export NOVA_GC_LIB_DIR="$M/compiler-codegen/vcpkg_installed/x64-windows-static/lib"      # Windows
export NOVA_GC_INCLUDE_DIR="$M/compiler-codegen/vcpkg_installed/x64-windows-static/include"
"$M/nova-cli/target/release/nova.exe" --help
```

| действие | команда | замечание |
|---|---|---|
| проверить типы одного файла | `nova check path/to/file.nv` | быстро; компилятор — единственный авторитет по синтаксису, не память |
| собрать бинарь | `nova build --mode release bin/claude_limits.nv -o target/claude-limits.exe` | из корня пакета, где `nova.toml` |
| тесты каталога | `nova test accounts/ --filter discover` | **путь обязателен**; `--filter` — подстрока имени теста |
| один тестовый файл | `nova test accounts/discover_test.nv` | |
| строгие эффекты | `nova build --strict-effects …` | так собираются соседние пакеты |
| линтер конвенций Nova | `nova lint <dir>` | |
| добавить зависимость | `nova add <pkg>` | обновляет `nova.lock.toml` |

Тесты — только через C-codegen (`nova test`); интерпретатора нет. Полный прогон чужих пакетов
(`nova test std`, мега-гейт `nova`) исполнитель задачи **не запускает**: только свои тесты и свой
каталог. Компилятор после правок в `nova/` пересобирается интегратором, не исполнителем.

### 2.2. Раскладка пакета

По канону Nova ([authoring-a-module](../../nova/docs/guide/authoring-a-module.md)): корень пакета =
корень исходников, `module a.b` = путь `a/b.nv`, тесты рядом с модулем в `*_test.nv`. Дерево
модулей — план 01 §3.2. Манифест `nova.toml` с `[[bin]]` и `[dependencies]` по git-тегам:
`http` (nova-http), `polaris` (nova-polaris), `tls` (nova-tls), `duckdb` (nova-duckdb), `sdl`
(nova-sdl). Версии тегов на момент написания — план 01 решение 5; актуальные — `git tag` в
соседнем репозитории.

Стиль `.nv` — [nv-coding-style](../../nova/docs/dev/nv-coding-style.md); устройство модулей с
эффектами и моками — [module-conventions](../../nova/docs/dev/module-conventions.md); FFI (только
для `nova-duckdb` и `nova-sdl`) — [ffi-cookbook](../../nova/docs/guide/ffi-cookbook.md).
Комментарии в коде и тексты диагностик — по-английски; строки интерфейса — по-английски (подплан
01.1 §0); документы проекта — по-русски.

### 2.5. Эталон и скрипты

`python scripts/claude_limits.py` печатает таблицу по учёткам и окнам; `--daemon` опрашивает раз в
`interval_sec`. Он источник истины для правил опроса и для формата `--once`. Дифференциал
`scripts/diff-with-probe.sh` (задача T1.8) и дым `scripts/smoke-server.sh` (T2.26) появляются в
проекте; их вызов — часть приёмки Ф.1 и Ф.2.

задача, добавляющая команду, дополняет таблицу.

## 4. Как устроена задача в 01.5

Каждая карточка:

- **входы** — какие разделы каких документов прочитать; читать больше не нужно, читать меньше нельзя;
- **выходы** — файлы, которые появляются или меняются;
- **готово, когда** — команды и ожидаемый результат; это и есть приёмка задачи;
- **зависит от** — карточки, без которых начинать нельзя;
- **размер** — S до 2 часов, M до 4, L до дня; L предупреждает, что задача крупная, но делить её
  дальше без потери смысла не вышло;
- **модель** — минимальная, которая справится: `haiku` для механики по образцу, `sonnet` для
  реализации по спецификации с небольшим выбором, `opus` для спайков и мест, где решение не записано.

Что в карточке не сказано, берётся из входов; чего нет и во входах — вопрос по §8, не догадка.

## 5. Тесты и приёмка задачи

- Тесты рядом с модулем (`<module>_test.nv`), эффекты подменяются моками (§2.3), реальных сети,
  файлов вне `fixtures/` и часов в `nova test` нет.
- **Оба направления** на каждый пункт: «делает» и «не делает» (не пишет в каталоги Claude Code,
  повторный вызов идемпотентен, чужой объект не тронут).
- **Обратная проба** обязательна: сломай собственное условие, увидь красный, верни, увидь зелёный.
  Вердикт пробы — дословно в отчёт. «Тесты зелёные» без пробы приёмкой не считается.
- Приёмка задачи — команды из «готово, когда» карточки; приёмка фазы — план 01 §6 и приёмки
  подпланов (01.1 §11, 01.2 §8, 01.3 §8); чек-листы конвенций (БД §17, API §20) — для задач, которые
  трогают схему или контракт.
- Тест ослаблять или удалять ради зелёного нельзя: тест авторитетен. Считаешь тест неверным —
  остановись и напиши (§8).

## 6. Отчёт

Файл `docs/reports/<id-задачи>.md` (например `docs/reports/T2.14.md`), по-русски, коротко:

```markdown
# T2.14 — PUT /api/config
Сделано: <2–4 строки: что появилось, что изменилось>
Проверено:
  $ nova test server/ --filter config          ← команда дословно
  <вывод: число тестов, итог>
  $ <вторая команда из карточки> …
Обратная проба: <что сломал → какой тест покраснел → вернул → зелёный>
Отклонения от входов: <нет | что и почему; ссылка на строку таблицы отклонений, если это отклонение от конвенции>
Открытые вопросы: <нет | вопрос с указанием, где искал ответ>
Дефекты Nova: <нет | ссылка на строку в nova/docs/plans/221.1-bug-sweep.md>
Модель: <haiku | sonnet | opus>
```

Строка «Проверено» без вывода команды отчётом не является. Приёмка фазы — отдельный файл
`docs/reports/F<n>-acceptance.md` с построчным ответом на приёмку из плана 01 §6.

## 7. Git

- Работа в своей ветке `task/<id>-<slug>` от `main`; `main` сливает интегратор.
- `git add` только по именам файлов: никаких `-A`, `.`, `-u`, `commit -a`.
- Перед коммитом `git diff --cached --stat`: в индексе может лежать чужое.
- Один коммит на задачу; сообщение по-английски: заголовок до 70 знаков, тело — что и почему.
- `git stash` не использовать; `push --force` и переписывание истории — нет.
- Файлы владельца в корне (`claude-limits.toml`, логи) не коммитить: они гитигнорятся или названы
  в карточке как «не трогать».

## 8. Когда остановиться и спросить

Остановка нужна ровно в этих случаях; во всех прочих — решение по документам и запись в отчёт.

1. **Контракт или схема требуют изменения**, которого нет в 01.2/01.3: новое поле, другой код
   ответа, другая таблица. Схема и контракт первичны, код под них.
2. **Нужно отступить от конвенции** (БД §16, API §19): отступление записывается в таблицу
   отклонений подплана **только владельцем или с его слова**.
3. **Новая зависимость** (пакет, C-библиотека, инструмент сборки) сверх перечисленных в плане 01.
4. **Спайк не сходится** или замер противоречит плану (например, `serve_tls` не тянет SSE): не
   «упростить», а записать цифры и остановиться.
5. **Компилятор противоречит спецификации или конвенции Nova**, или падает на законном коде: не
   обходить, а завести строку в `nova/docs/plans/221.1-bug-sweep.md` с `№TBD`, приоритетом и
   минимальным воспроизведением, сослаться на неё в отчёте и продолжить независимую часть задачи.
6. **Два документа проекта противоречат друг другу**: обе цитаты в отчёт, выбор не исполнителя.

Не повод останавливаться: имя локальной переменной, порядок функций в файле, формулировка теста,
выбор между двумя равнозначными std-функциями. Это решается и записывается одной строкой в отчёт.

## 9. Чего исполнитель не делает никогда

- Не пишет в каталоги Claude Code и не читает из них ничего сверх двух файлов, названных в README.
- Не кладёт токены, почты и пути с именем пользователя в логи, URL, тесты, отчёты, сообщения коммитов.
- Не запускает сеть из `nova test`; не ходит на эндпоинт Anthropic чаще, чем раз в 60 секунд, и
  только с живым токеном (`--once` и дым).
- Не меняет конвенции и планы, кроме строк, которые карточка прямо велит обновить (таблица CLI в
  этом файле, `fixtures/README.md`, реестр ПДн при новой колонке).
- Не спавнит вложенных агентов и не запускает чужие полные тестовые прогоны.
