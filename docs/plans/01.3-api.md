# План 01.3 — HTTP API бэкенда: маршруты, схемы, ошибки, события, доступ

**Статус:** ПРЕДЛОЖЕН 2026-09-06, **приведён к редакции 1.0 [конвенции по API](../conventions/api.md)**
(RFC 9457, правило про URL, `If-Match` с `412`/`428`, `X-Request-Id`, вход в LAN через `POST
/api/session`, TLS для LAN). **Подплан** плана [01-widget-on-nova.md](01-widget-on-nova.md): контракт
между бэкендом (`server/`) и его потребителями — страницей (подплан [01.1](01.1-browser-page-spec.md)),
виджетом (читает снимок из памяти, но те же типы), скриптами (`curl`, дифференциал с
`claude_limits.py`) и телефоном в LAN. Хранение, на которое опираются ответы, — подплан
[01.2](01.2-storage.md). Реализуется фазой Ф.2 плана 01; собственных фаз нет. Отклонения от
конвенции собраны в §9.

Факты сверены по `nova-polaris` 2026-09-06: `Router`, `serve_router(TcpListener, …)`,
`ServerResponse.sse` + `StreamBody`/`stream_body`, `static_handler` + `embed_dir`, извлекатели
`Query[T]`, `Json[T]`, `PathParam[T]`, `Bearer.from_request` + `unauthorized_bearer()`,
`openapi_json(routes, title, version)` / `openapi_handler` (`src/openapi.nv:376,401`), `serve_once` для
тестов без сокета. **TLS-слушателя у Polaris нет**; `nova-tls` умеет серверную сторону
(`TlsStream.accept(TcpStream, ServerConfig)`, `src/server.nv:53`), генерации сертификатов ни в
`nova-tls`, ни в std нет. Следствие для LAN-режима — §1.

## 0. Соглашения

- **Базовый адрес** `http://127.0.0.1:7391` (порт из конфига). Все машинные маршруты — под `/api/`;
  всё остальное — страница и её встроенные файлы. **Версии в пути нет** (отклонение D1, §9): клиент
  и сервер — один бинарь; для внешних скриптов `GET /api/health` возвращает `api_version` (целое,
  растёт при несовместимом изменении), и в каждом ответе есть заголовок `X-Api-Version`.
- **JSON**: `Content-Type: application/json; charset=utf-8`, ключи `snake_case`, отсутствующее
  значение — `null`, а не пропуск ключа; списки — всегда списки, даже пустые; верхний уровень —
  всегда объект; массивы именованные. Числа процентов — целые; доли (`elapsed_share`,
  `rate_per_hour`) — числа JSON с фиксированной точностью 2–3 знака (не деньги, ошибка
  округления безвредна). Перечисления — латиница `snake_case` (`working_hours`, не
  `working-hours`).
- **Время** — ISO 8601 строго в UTC с суффиксом `Z` (`2026-09-06T18:10:00Z`): смещений в ответах нет,
  эндпоинт Anthropic отдаёт смещение, бэкенд переводит в UTC при разборе; пояс бэкенда для подписей —
  поле `tz` (IANA) в `/api/snapshot`; страница считает оси в поясе браузера. Длительности — секунды
  целым с суффиксом в имени (`seconds_left`, `interval_sec`). Готовые подписи вида `2d 17h` сервер даёт
  полями `*_label` **рядом** с машинным значением, никогда вместо него (отклонение D2, §9): страница
  и виджет показывают одно и то же (план 01 §3.4, `model/format.nv`).
- **В URL нет персональных данных**: ни почт, ни путей каталогов (в них имя пользователя ОС), ни
  токенов — ни в пути, ни в query (конвенция §2.3). Учётки и каталоги адресуются **идентификаторами
  UUID v7 из базы** (`account_id`, `login_dir_id`, `folder_id`, подплан 01.2 §3.1); почты и пути
  живут только в телах. Список query-параметров у каждого маршрута закрыт; неизвестный или
  повторённый не-массивный параметр — `400 invalid_parameter`.
- **Ошибки** — RFC 9457 Problem Details, `Content-Type: application/problem+json; charset=utf-8`:
  ```json
  {
    "type": "urn:claude-limits:problem:invalid-config",
    "title": "Invalid settings",
    "status": 422,
    "detail": "minimum is 60 s (the server rate-limits eager polling)",
    "instance": "/api/config",
    "code": "invalid_config",
    "request_id": "0192a7f0-3c4d-7e21-8a55-0b9c1d2e3f40",
    "retry_after": null,
    "errors": [ { "field": "poll.interval_sec", "code": "less_than_min", "message": "minimum is 60 s (the server rate-limits eager polling)" } ]
  }
  ```
  `code` — из закрытого списка §6, `type` — `urn:claude-limits:problem:` + `code` с дефисами,
  `instance` — шаблон пути (`/api/accounts/{id}`), `request_id` — как в заголовке `X-Request-Id`,
  `errors[]` — только у ошибок валидации, `field` — путь в теле или имя параметра. Тексты —
  английские (язык интерфейса, подплан 01.1 §0). HTML-ошибок для `/api/*` нет; для `/` при
  внутренней ошибке — краткая страница с тем же текстом и `request_id`.
- **`400` против `422`**: `400` — не разобрали или обратились неправильно (битый JSON, лишний
  query-параметр, `from` позже `to`, слишком большой диапазон); `422` — разобрали, но так нельзя
  (значение поля вне правил, лишнее поле тела, `bind` не loopback без TLS).
- **Методы**: `GET` — чтение без побочных эффектов, `POST` — действие, `PUT` — замена настроек
  целиком после слияния (§3.8), `DELETE` — только `/api/session`. `HEAD` и `OPTIONS` отвечают как
  Polaris по умолчанию. Неизвестный путь под `/api/` — `404`; неизвестный метод — `405` с `Allow`;
  тело не `application/json` там, где тело нужно — `415 unsupported_media_type`; тело больше
  256 КБ — `413 body_too_large`.
- **Заголовки каждого ответа**, включая ошибки и `204`: `X-Request-Id` (UUID v7, генерирует
  middleware; валидный входящий переиспользуется), `X-Api-Version`, `Cache-Control` (`no-store` для
  всего под `/api/`; страница и статика — `ETag` от `static_handler` и `no-cache`),
  `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `X-Frame-Options: DENY`.
  `Retry-After` — на каждом `429` и `503`. Заголовков `Server` и иных, называющих фреймворк или
  версию, в ответе нет (Polaris по умолчанию — проверяется приёмкой §8 п. 11).
- **Токены учёток в ответах не появляются никогда**; тесты §8 ищут их подстрокой.

## 1. Доступ

| режим | кто может | как |
|---|---|---|
| `bind = 127.0.0.1` (по умолчанию) | любой процесс этой машины | без учётных данных; заголовок `Authorization` и cookie игнорируются; TLS нет (конвенция §1.1: loopback) |
| `bind ≠ loopback` (`allow_lan = true`) | тот, у кого `access_token` | **только по TLS** (ниже); скрипты — `Authorization: Bearer <access_token>` на `/api/*`; браузер — сессия через `POST /api/session` (§3.13) |

**TLS в LAN-режиме обязателен** (конвенция §1.1): `allow_lan = true` требует `[server] tls_cert` и
`tls_key` (PEM; создать `openssl req -x509 -newkey ec …` или `mkcert`, шаги — в README), иначе
валидация конфига даёт `422 invalid_config` с `field: server.tls_cert` и слушатель остаётся на
loopback. Самоподписанный сертификат достаточен: отпечаток показывается в панели настроек рядом
с адресом, телефон принимает его один раз. **Предпосылка**: `serve_router` Polaris принимает
`TcpListener` и не знает TLS; нужен слушатель, оборачивающий принятые соединения в
`TlsStream.accept` из `nova-tls` (задача в план 01 Ф.2, оценка — отдельный спайк). До её появления
LAN-режим не собирается: тумблер в UI неактивен с подсказкой `TLS listener not available in this
build`. Открытый HTTP на сетевом интерфейсе не включается ни при каком флаге.

**Два вида учётных данных, у каждого маршрута — ровно один** (конвенция §1.2):

| учётные данные | маршруты | зачем |
|---|---|---|
| `Authorization: Bearer <access_token>` из конфига | все `/api/*`, кроме перечисленных ниже | скрипты и страница (страница держит короткоживущий сессионный bearer в памяти вкладки, см. §3.13) |
| cookie `cl_session` (случайный идентификатор, `HttpOnly; Secure; SameSite=Strict; Path=/`, 30 дней) | `GET /`, `GET /login`, `GET /assets/*`, `GET /api/events`, `POST /api/session/token`, `DELETE /api/session` | то, чему браузер не даёт поставить заголовок: загрузка страницы, статика, `EventSource` |

Без учётных данных: `/api/health` доступен всем (только `ok` и `api_version`), `GET /` и `/assets/*`
без cookie отдают `/login` (`303`), остальное — `401 unauthenticated` с `WWW-Authenticate: Bearer`
на bearer-маршрутах (у них схема действительно Bearer) и без него на cookie-маршрутах. Cookie в
LAN-режиме ставится только по TLS (`Secure`); на loopback сессий нет вовсе.

Проверка `access_token` — сравнение за константное время; неверный токен или сессия считаются и
логируются (адрес, время), после 10 неверных за минуту с одного адреса — `429
too_many_auth_failures` с `Retry-After: 60`. Смена токена в конфиге обнуляет все сессии (`cl_session`
хранит хэш токена, под которым выдана). На изменяющих запросах (`POST`, `PUT`, `DELETE`) с
cookie-сессией проверяется `Origin`: он обязан совпадать с адресом слушателя; отсутствие —
отказ `403 origin_required`. Для bearer-запросов `Origin` не проверяется (браузерного источника у
них нет). Адрес клиента — адрес соединения: доверенных прокси у продукта нет, `X-Forwarded-For`
игнорируется.

Заголовки на страницу: `Content-Security-Policy: default-src 'none'; script-src 'self'; style-src
'self'; font-src 'self'; img-src 'self' data:; connect-src 'self'` (внешних ресурсов у страницы нет,
подплан 01.1 §0); в LAN-режиме — `Strict-Transport-Security: max-age=31536000`. CORS не включается:
другим origin API не нужен.

| `GET /` | страница | `text/html` | cookie | 3.1 |
| `GET /login` | форма ввода токена (LAN) | `text/html` | нет | 3.1 |
| `GET /assets/{*path}` | шрифты, иконка | по mime | cookie | 3.1 |

| `POST /api/refresh` | опросить сейчас | `202` / `429` | bearer | 3.5 |

отвечают `404`.

## 3. Маршруты

### 3.1. `GET /`, `GET /login`, `GET /assets/{*path}`

`index.html`, `login.html`, `manrope-*.woff2`, `jetbrains-mono-*.woff2`, `icon.svg` из
`embed_dir("web")` через `static_handler` (ETag, mime, 404). Любой другой путь вне `/api/` —
`index.html` (страница сама показывает вид из `localStorage`; глубоких ссылок нет, кроме `/#stats`,
`/#cards` как якорей). `/login` — одна форма с полем токена, отправляет `POST /api/session` (§3.13);
токен в URL не передаётся никогда.

  `resets_at`, поле — для виджета и скриптов).
- `forecast` — `null`, если недоступен (подплан 01.1 §2.7); `basis` ∈ `clock | working_hours`;
  `warning: true` ⇔ `runs_out_at` раньше `resets_at`.
- `at_100` — есть окно с `percent = 100` без `locked_reason`; `locked` — есть `locked_reason`. Оба
  красят плашку.
- Порядок `accounts` — `ui.accounts_order`, затем остальные по первому появлению; скрытые
  (`ui.hidden_accounts`) **не входят**; `?include_hidden=1` включает их (для настроек). Других
  query-параметров у маршрута нет.
- `limits` пуст у `stale`/`error`; у `unknown` — последний удачный снимок с `polled_at` того снимка.

### 3.4. `GET /api/events` — Server-Sent Events

`Content-Type: text/event-stream`, `Connection: keep-alive`, через `ServerResponse.sse` и
pull-продюсер `stream_body` над `Chan` подписки у `store` (`examples/07-sse-stream`). Query-параметров
нет; в LAN-режиме — cookie (`EventSource` не умеет заголовков) или bearer для скриптов. При
подключении — сразу событие `snapshot` (текущее), затем по факту:

| `event:` | `data:` | когда |
|---|---|---|
| `snapshot` | тело §3.3 целиком | после каждого опроса любой учётки, после `POST /api/refresh`, при восстановлении из базы |
| `config` | тело §3.7 | после успешного `PUT /api/config`, после подхвата изменённого файла |
| `folders` | `{ "login_dirs": 5, "changed": [ { "id": "…", "name": "dev" } ] }` | обнаружение нашло/потеряло каталог или сменилась почта в нём |
| `notice` | `{ "level": "warning", "text": "config error: [poll] interval_sec must be a number" }` | ошибка чтения конфига, проблемы базы (подплан 01.2 §5), переоткрытие слушателя |
| `ping` | `{ "at": "…" }` | раз в 30 с при тишине |
| `bye` | `{ "reason": "shutdown" }` | остановка сервера, переоткрытие слушателя |

Каждое событие несёт `id:` (монотонный счётчик); клиент присылает `Last-Event-ID`, и если
пропущено не больше 100 событий — сервер досылает пропущенные из кольцевого буфера, иначе —
свежий `snapshot`. Лимит одновременных подписок — 32; 33-я получает `503 too_many_subscribers` с
`Retry-After: 30`. В LAN-режиме тело событий `snapshot` — то же, что у `GET /api/snapshot` из LAN
(`dirs[].path = null`).

### 3.5. `POST /api/refresh`

Тело `{}` (все учётки) или `{ "account_id": "0192a7f0-…" }`. Ответы:

- `202 Accepted` `{ "queued": [ { "id": "…", "email": "main@example.com" } ], "expect_event": "snapshot" }` —
  опрос поставлен в очередь, результат придёт событием; отдельного ресурса задачи нет
  (отклонение D5, §9);
- `429 too_soon` + `Retry-After` (`retry_after` в теле дублирует секунды) — пол 60 с с прошлого
  опроса или backoff после 429 эндпоинта (план 01 §0);
- `404 account_not_found` — неизвестный `account_id`; `409 account_stale` — у учётки протух токен,
  опрашивать нечего; `422 extra_forbidden` — лишнее поле в теле (например, `email`).

### 3.6. `GET /api/history`

### 3.8. `PUT /api/config`

Тело — **частичное** дерево `config` (только изменяемые ветки); сервер сливает его с текущим
конфигом ключ-в-ключ (списки заменяются целиком), валидирует как при старте, пишет файл атомарно
(подплан 01.2 §2.2) и применяет. Обязателен заголовок `If-Match: <etag из GET>` (конвенция §9.4).
Элемент `folders[]` задаётся либо `{ "id": "…" }` (существующая папка), либо `{ "path": "…" }` (новая);
папки, отсутствующие в списке, удаляются из конфига.

```json
PUT /api/config
If-Match: "a1b2c3-1725641222"
{ "poll": { "interval_sec": 120 }, "folders": [ { "id": "…" }, { "path": "~/.claude" } ], "ui": { "accounts_order": ["work@example.org", "main@example.com"] } }
```

Ответы:

- `200` — тело как у `GET /api/config` с новым `etag`, плюс `"applied": { "restart_required": false,
  "listener_reopened": false }`; всем подписчикам — событие `config`;
- `428 precondition_required` — нет `If-Match`;
- `412 precondition_failed` — файл менялся после `If-Match` (правка руками или другой вкладкой);
  тело ошибки содержит поле `current` с актуальным `GET /api/config`, панель предлагает
  перечитать;
- `400 invalid_body` — тело не JSON; `415` — не `application/json`; `413 body_too_large`;
- `422 extra_forbidden` — ключ, которого нет в дереве настроек (`errors[].field` в точечной
  нотации: `poll.intervalSec`); `422 invalid_config` — значение вне правил, `errors[]` по одному на
  поле (`poll.interval_sec`, `folders[2].path`, `forecast.work_days`, `server.tls_cert`), тексты —
  подплан 01.1 §5; все ошибки в одном ответе;
- `500 config_readonly` — файл недоступен для записи (права, диск); `detail` с причиной,
  `request_id`.

Смена `server.bind`/`port`/`access_token`/`tls_*`: применяется переоткрытием слушателя после
ответа `200` с `"listener_reopened": true` и полем `"new_base_url"`; текущее SSE-соединение получает
`notice` и `bye`. Смена `folders` запускает обнаружение немедленно и шлёт `folders` + `snapshot`.
Изменения только `ui.*` не трогают поллеры. Повтор того же `PUT` после успеха получает `412`:
идемпотентность через версию ресурса (конвенция §10.3), клиент перечитывает `GET /api/config`.

### 3.9. `POST /api/folders/probe`

Проверить путь до добавления (строка «что найдено» в панели настроек, подплан 01.1 §5.4). Ничего не
пишет; путь — в теле, не в URL.

```json
POST /api/folders/probe  { "path": "\\\\wsl.localhost\\Ubuntu\\home\\me\\.claude" }
→ 200 { "path_resolved": "//wsl.localhost/Ubuntu/home/me/.claude", "kind": "single",
        "login_dirs": [ { "name": ".claude", "email": "work@example.org", "org": "Personal", "token_state": "ok", "same_login_as": [ { "id": "…", "name": "dev" } ] } ],
        "problem": null, "already_listed": false }
```

`kind` ∈ `single | parent | empty | missing`; `problem` — текст для янтарной/красной строки или
`null`. Для `parent` — все дочерние с логином. Чтение каталогов — только `.claude.json` и факт
наличия `.credentials.json` (`expiresAt` для `token_state`); содержимое токена не читается.
`path_resolved` в LAN — `null`.

### 3.10. `POST /api/config/token`

Сгенерировать `access_token` (32 байта из CSPRNG, base64url). Требует `If-Match` как §3.8 (повтор
после успеха — `412`, второй токен не выпускается). Ответ `200 { "access_token": "…", "shown_once":
true }` — единственный раз, когда токен виден в API; сервер сразу пишет его в конфиг и включает
`allow_lan`, если тело `{ "allow_lan": true }` и TLS настроен. Доступен только с loopback: из LAN —
`403 loopback_only` (отказ относится к вызывающему целиком, объекта не раскрывает).

### 3.11. `GET /api/export`

Параметры как у §3.6 плюс `format=csv|json` (по умолчанию `csv`) и `unmasked=1` (только loopback;
из LAN — `403 loopback_only`). CSV: `at,account_id,email,kind,model,percent,locked,resets_at`
построчно; почты по умолчанию замаскированы (`m***@example.com`, подплан 01.2 §10);
`Content-Disposition: attachment; filename="claude-limits-2026-08-07..2026-09-06.csv"`. Потоковый
ответ (`ServerResponse.stream`), без предела по размеру. Та же выгрузка из CLI — `claude-limits export`.

### 3.12. `GET /api/openapi.json`

`openapi_handler(routes, "claude-limits", api_version)` Polaris по зарегистрированным
типизированным маршрутам (`*_typed`): схемы `Query[HistoryQuery]`, `Json[ConfigPatch]`,
`Json[ProbeRequest]`, `Json[SessionRequest]` попадают в описание автоматически; общие компоненты
`Problem`, `ValidationProblem`; примеры из этого подплана — `x-example`; у каждого поля с ПДн —
`x-data-class: pii` (почты, пути), у идентификаторов — `none`. В LAN — только с bearer (спецификация
не публикуется без учётных данных, конвенция §14.1). Это же описание — приёмка §8 п. 9.

### 3.13. `POST /api/session`, `POST /api/session/token`, `DELETE /api/session` (только LAN)

Вход браузера без токена в URL (конвенция §1.2):

1. `GET /` без cookie → `303` на `/login`; форма отправляет `POST /api/session` с телом
   `{ "access_token": "…" }` (`Content-Type: application/json`, страница `login.html` делает это
   `fetch`-ом). Успех — `204` с `Set-Cookie: cl_session=<32 байта base64url>; HttpOnly; Secure;
   SameSite=Strict; Path=/; Max-Age=2592000`, страница переходит на `/`. Неверный токен — `401
   unauthenticated`, счётчик неверных (§1).
2. Страница при загрузке вызывает `POST /api/session/token` (cookie) → `200 { "session_token": "…",
   "expires_at": "…" }`: короткоживущий (12 ч) bearer, живущий в памяти вкладки; все `fetch` к `/api/*`
   идут с `Authorization: Bearer <session_token>`. `EventSource('/api/events')` идёт с cookie.
   Сессионный токен принимается bearer-маршрутами наравне с `access_token` и умирает вместе с
   сессией; `access_token` в JavaScript страницы не попадает.
3. `DELETE /api/session` (cookie, `Origin` обязателен) → `204`, cookie сброшен, сессионные токены
   отозваны.

Сессии живут в памяти `store` (при перезапуске — вход заново); их не больше 16, старейшая
вытесняется. На loopback маршруты отвечают `404`.

## 4. Реализация в Polaris

```
server/
├── routes.nv      Router: статика (static_handler над embed_dir("web")), /api/* через *_typed;
│                  порядок middleware: request_id → limits (размер тела, заголовки) → security_headers →
│                  access_log → auth (bearer | cookie по таблице §1, только при allow_lan) → маршруты
├── listener.nv    TcpListener; в LAN-режиме — обёртка TlsStream.accept из nova-tls (предпосылка §1)
├── auth.nv        Bearer.from_request | cookie cl_session; константное сравнение; счётчик неверных по адресу;
│                  проверка Origin на изменяющих cookie-запросах; сессии и сессионные токены
├── handlers/
│   ├── health.nv, snapshot.nv, refresh.nv, history.nv, config.nv, folders.nv, token.nv, export.nv, session.nv
│   └── events.nv  подписка на Chan у store → stream_body; Last-Event-ID; лимит 32
├── dto.nv         типы ответов/запросов (serde JSON); один источник для страницы, виджета и OpenAPI;
│                  сериализация в LAN обнуляет поля класса pii-path (dirs[].path, config.path, …)
├── errors.nv      ApiError { code, status, detail, field?, errors?, retry_after? } → problem+json с type, instance, request_id
└── json.nv        сериализация Snapshot → dto без токенов (тест §8 п. 2)
```

- Хендлеры не трогают базу и файлы напрямую: всё через `Chan` к файберу `store` (план 01 §3.1) —
  запрос/ответ с таймаутом 5 с, по таймауту `503 store_busy` с `Retry-After: 5`.
- `serve_router(listener, app, ServerPolicy.new().max_connections(64).read_timeout(15s))`; тело
  запроса ограничено 256 КБ (`PUT /api/config` с сотней папок — килобайты).
- Логи доступа — `polaris.log`, строка на запрос: `request_id`, метод, шаблон пути, статус,
  длительность, адрес клиента. URL пишется целиком: по правилу §0 в нём нет ПДн и токенов. Тела
  запросов и ответов в лог не пишутся ни на каком уровне. Уровень `warn` для `4xx/5xx`.

## 5. Совместимость, эволюция, повторы

- Добавление поля в ответ — не ломающее; удаление или смена типа — `api_version + 1` и запись
  здесь. Страница проверяет `api_version` из `/api/health` при загрузке и просит перезагрузить
  вкладку, если бинарь обновился (событие `notice` со `level: "reload"` при старте новой версии).
- **Повторы на стороне страницы и виджета** (конвенция §17): автоматически повторяются только
  `GET`; не более трёх попыток с задержкой 0,5 → 1 → 2 с и разбросом ±20 %; `Retry-After`
  перекрывает расчёт; `4xx`, кроме `429`, не повторяются; `POST /api/refresh` и `PUT /api/config`
  повторяются только по нажатию человека (`PUT` — после перечитывания при `412`). При обрыве SSE —
  переподключение через 30 с и опрос `/api/snapshot` раз в 10 с (подплан 01.1 §1).
- Дифференциал с эталоном (план 01, решение 10): `scripts/diff-with-probe.sh --api` превращает
  `GET /api/snapshot` в таблицу `email / kind / percent / severity / resets_at` и сравнивает с выводом
  `claude_limits.py` побайтно; поля `id`, `forecast`, `elapsed_share`, `*_label` в дифференциал не
  входят — эталон их не считает.

## 6. Коды ошибок

`type` = `urn:claude-limits:problem:<code через дефисы>`; список закрыт, новый код — правка этой
таблицы.

|---|---|---|
| 400 | `invalid_body` (не JSON), `invalid_parameter` (неизвестный/неверный query-параметр, `from ≥ to`), `range_too_large` | §3.6, §3.8, §3.11 |
| 401 | `unauthenticated` | §1, §3.13 |
| 403 | `loopback_only`, `origin_required` | §3.10, §3.11, §1 |
| 404 | `not_found`, `account_not_found` | любой, §3.5 |
| 405 | `method_not_allowed` (+ `Allow`) | любой |
| 409 | `account_stale` | §3.5 |
| 412 | `precondition_failed` (тело несёт `current`) | §3.8, §3.10 |
| 413 | `body_too_large` | тело > 256 КБ |
| 415 | `unsupported_media_type` | тело не `application/json` |
| 422 | `invalid_config`, `extra_forbidden`, `invalid_request` (`errors[]` обязателен) | §3.5, §3.8, §3.9, §3.13 |

| 429 | `too_soon`, `too_many_auth_failures` (+ `Retry-After`) | §3.5, §1 |

```bash
ACC=$(curl -s http://127.0.0.1:7391/api/snapshot | jq -r '.accounts[0].id')
curl -s "http://127.0.0.1:7391/api/history?range=30d&by=folder&step=day&account_id=$ACC" | jq '.folders[].occupancy'
ETAG=$(curl -si http://127.0.0.1:7391/api/config | awk -F': ' '/^ETag/{print $2}' | tr -d '\r')
curl -s -X PUT -H "If-Match: $ETAG" -H 'Content-Type: application/json' -d '{"poll":{"interval_sec":120}}' http://127.0.0.1:7391/api/config
curl -s --cacert cl.pem -H 'Authorization: Bearer <token>' https://192.168.1.10:7391/api/snapshot   # из LAN, только TLS
```

## 8. Приёмка (часть Ф.2 плана 01)

Тесты — через `serve_once` без сокета (`nova-polaris/docs/overview.md`), фикстуры — из плана 01 §7;
живая сеть — только `scripts/smoke-server.sh`.

1. Каждый маршрут §2 отвечает заявленным статусом и `Content-Type`; неизвестный `/api/x` — `404`
   problem+json; `/api/snapshot` методом `POST` — `405` с `Allow: GET, HEAD`; `PUT /api/config` с
   `text/plain` — `415`; тело 300 КБ — `413`.
2. Ни один ответ (включая `500`, `notice`, `export`) не содержит подстрок токенов из фикстур;
   обратная проба — нарочно положить токен в `detail` → тест краснеет.
3. `snapshot`: порядок учёток по `accounts_order`; скрытые отсутствуют без `include_hidden`;
   `?email=x` — `400 invalid_parameter`; `severity` считается по порогам конфига (порог 50 в фикстуре
   делает 61 % `warning`); `forecast: null` для `stale`/`unknown`/`locked`; `basis` ∈ `clock |
   working_hours`; в LAN-режиме `dirs[].path` — `null`.
4. `events`: первое событие — `snapshot`; `POST /api/refresh` → `snapshot` в течение тика мока;
   `Last-Event-ID` с отставанием 3 → досылка 3 событий; 33-я подписка — `503` с `Retry-After`.
5. `refresh`: второй вызов в пределах 60 с — `429` с корректным `Retry-After` в заголовке и теле;
   после 429 эндпоинта — `Retry-After` из его заголовка; тело `{ "email": "…" }` — `422
   extra_forbidden`.
6. `history`: `7d`/`by=account` из фикстуры на 7 дней даёт `2016` точек на окно при `step=300`;
   `resets`, `locks`, `gaps` совпадают с ожидаемыми интервалами; `by=folder` при смене почты в фикстуре
   даёт два `segments` и две записи `occupancy`; `> 50 000` точек — `400 range_too_large`; неизвестный
   `account_id` — пустой список; `from ≥ to` — `400`.
7. `config`: `PUT` без `If-Match` — `428`; с устаревшим — `412` и `current` в теле; повтор успешного
   `PUT` — `412`; неизвестный ключ — `422 extra_forbidden` с точным `field`; две ошибки значений —
   один `422` с двумя `errors[]`; успешный — новый `etag`, событие `config`, файл переписан
   канонически (подплан 01.2 §8 п. 2); `allow_lan = true` без `tls_cert` — `422` с `field:
   server.tls_cert`; `GET` с `If-None-Match` — `304`.
8. Доступ (LAN-режим с тестовым сертификатом из `nova-tls/src/testdata`): запрос без учётных
   данных — `401` problem+json, `WWW-Authenticate: Bearer` только на bearer-маршрутах; `GET /` без
   cookie — `303 /login`; `POST /api/session` с верным токеном — `204` и cookie с `HttpOnly; Secure;
   SameSite=Strict`; `POST /api/session/token` — bearer, принимаемый `/api/snapshot`; `DELETE
   /api/session` без `Origin` — `403 origin_required`; смена токена в конфиге → старая сессия `401`;
   10 неверных токенов — `429` с `Retry-After`; `/api/config/token` и `export?unmasked=1` из LAN —
   `403`; `/api/health` из LAN — без путей и версии; открытый HTTP на `0.0.0.0` не поднимается
   ни при каком конфиге.
9. `openapi.json` валиден (проверка схемы OpenAPI 3.x в CI), перечисляет все маршруты §2, у каждого
   ответа `4xx/5xx` — ссылка на общий компонент `Problem`, ни одного параметра из чёрного списка
   конвенции (`email`, `path`, `token`) с `in: query` или `in: path`; у полей с почтами и путями —
   `x-data-class: pii`.
10. `smoke-server.sh`: поднять бинарь, `health`, `snapshot`, три события SSE после `refresh`, `export`
    в CSV с правильным числом строк и замаскированными почтами, корректное завершение по сигналу
    (`bye` подписчикам).
11. Заголовки: у каждого ответа, включая `204`, `304` и ошибки, есть `X-Request-Id` (валидный UUID v7,
    входящий валидный переиспользован), `X-Api-Version`, `Cache-Control`; у каждого `429` и `503` —
    `Retry-After`; заголовка `Server` нет; журнал доступа не содержит тел и содержит `request_id`.

## 9. Отклонения от конвенции по API

Конвенция — [`docs/conventions/api.md`](../conventions/api.md), §19 требует записывать каждое
отклонение с причиной, ценой и условием снятия.

| № | правило | отклонение | почему | цена | снимается, когда |
|---|---|---|---|---|---|
| D1 | версия в пути `/api/v<major>` (§2.1) | `api_version` в `/api/health` и заголовке `X-Api-Version` | клиент и сервер — один бинарь; внешние потребители — скрипты владельца | скрипт проверяет версию сам | появится потребитель, который деплоится отдельно |
| D2 | подписи формирует интерфейс (§11) | поля `*_label` рядом с машинными значениями | два интерфейса (страница и виджет) и дифференциал с эталоном должны показывать одну строку | клиент не может сменить формат подписи | — (постоянное) |
| D3 | набор заголовков §9.2 (`traceparent`, модуль, экземпляр, тайминги) | не отдаются | один процесс, распределённой трассировки нет | разбор инцидента только по `request_id` и логу одного процесса | второй сервис в цепочке |
| D4 | cookie только где заголовок невозможен (§1.2) | cookie принимают также `POST /api/session/token` и `DELETE /api/session` | иначе странице нечем получить сессионный bearer после перезагрузки | два cookie-маршрута с побочными эффектами; закрыто `Origin` + `SameSite=Strict` | — (постоянное) |
| D5 | `202` с ресурсом задачи и `Location` (§7.1, §13) | `202` без ресурса задачи; результат приходит событием SSE | опрос длится секунды и виден всем подписчикам; ресурс задачи дублировал бы `snapshot` | скрипт без SSE ждёт следующий `snapshot` | появится долгая фоновая операция |
| D6 | коллекции с курсором (§4) | `history` без пагинации, ограничен диапазоном и шагом | объём ограничен по построению, превышение — громкий `400` | клиент подбирает `step` сам | — (постоянное) |
| D7 | `search` для фильтров с ПДн (§2.4) | не нужен | все фильтры — по UUID; почты и пути в URL запрещены и не принимаются | — | — |
| D8 | сессия по бездействию (§8.2) | сессия LAN живёт 30 дней без бездействия; `session_expired` не используется | один пользователь, свои устройства; сессия отзывается сменой токена или `DELETE /api/session` | украденный cookie живёт до отзыва | несколько пользователей |
