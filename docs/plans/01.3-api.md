# План 01.3 — HTTP API бэкенда: маршруты, схемы, ошибки, события, доступ

**Статус:** ПРЕДЛОЖЕН 2026-09-06. **Подплан** плана [01-widget-on-nova.md](01-widget-on-nova.md):
контракт между бэкендом (`server/`) и его потребителями — страницей (подплан
[01.1](01.1-browser-page-spec.md)), виджетом (читает снимок из памяти, но те же типы),
скриптами (`curl`, дифференциал с `claude_limits.py`) и телефоном в LAN. Хранение, на которое
опираются ответы, — подплан [01.2](01.2-storage.md). Реализуется фазой Ф.2 плана 01;
собственных фаз нет.

Факты сверены по `nova-polaris` 2026-09-06: `Router`, `serve_router`, `ServerResponse.sse` +
`StreamBody`/`stream_body`, `static_handler` + `embed_dir`, извлекатели `Query[T]`, `Json[T]`,
`PathParam[T]`, `Bearer.from_request` + `unauthorized_bearer()`, `openapi_json(routes, title,
version)` / `openapi_handler` (`src/openapi.nv:376,401`), `serve_once` для тестов без сокета.

## 0. Соглашения

- **Базовый адрес** `http://127.0.0.1:7391` (порт из конфига). Все машинные маршруты — под
  `/api/`; всё остальное — страница и её встроенные файлы. Версии в пути нет: API локальный,
  клиент и сервер — один бинарь; для внешних скриптов `GET /api/health` возвращает `api_version`
  (целое, растёт при несовместимом изменении) и в каждом ответе есть заголовок `X-Api-Version`.
- **JSON**: `Content-Type: application/json; charset=utf-8`, ключи `snake_case`, отсутствующее
  значение — `null`, а не пропуск ключа; списки — всегда списки, даже пустые. Числа процентов —
  целые. **Время** — строка ISO-8601 с смещением локального пояса бэкенда
  (`2026-09-06T21:10:00+03:00`), как у эндпоинта Anthropic; длительности — секунды целым
  (`seconds_left`), подписи вида `2d 17h` сервер даёт готовыми полями `*_label`, чтобы страница и
  виджет показывали одно и то же (план 01 §3.4, `model/format.nv`).
- **Ошибки** — единый конверт:
  ```json
  { "error": { "code": "invalid_config", "message": "minimum is 60 s (the server rate-limits eager polling)", "field": "poll.interval_sec", "retry_after": null } }
  ```
  `code` — из закрытого списка §6, `field` и `retry_after` — по смыслу или `null`. HTML-ошибок для
  `/api/*` нет; для `/` при внутренней ошибке — краткая страница с тем же текстом.
- **Методы**: `GET` — чтение без побочных эффектов, `POST` — действие, `PUT` — замена настроек
  целиком после слияния (см. §3.8), `DELETE` — нет (папки удаляются через `PUT /api/config`).
  `HEAD` и `OPTIONS` отвечают как Polaris по умолчанию. Неизвестный путь под `/api/` — `404`
  с конвертом; неизвестный метод — `405` с `Allow`.
- **Кэш**: `Cache-Control: no-store` на всё под `/api/`; страница и статика — `ETag` от
  `static_handler`, `Cache-Control: no-cache` (проверять всегда, тело не качать без нужды).
- **Токены учёток в ответах не появляются никогда**; тесты §8 ищут их подстрокой.

## 1. Доступ

| режим | кто может | как |
|---|---|---|
| `bind = 127.0.0.1` (по умолчанию) | любой процесс этой машины | без токена; заголовок `Authorization` игнорируется |
| `bind ≠ loopback` (`allow_lan = true`) | тот, у кого `access_token` | `Authorization: Bearer <token>` для `/api/*`; для страницы — один раз `GET /?token=<token>` → `Set-Cookie: cl_token=<token>; HttpOnly; SameSite=Strict; Path=/` и редирект `303` на `/` без параметра; дальше cookie принимается наравне с Bearer. `/api/health` доступен без токена (только `ok` и `api_version`), остальное — `401` с `WWW-Authenticate: Bearer` (`unauthorized_bearer()`) |

Проверка токена — константное по времени сравнение; неверный токен считается и логируется
(адрес, время), после 10 неверных за минуту с одного адреса — `429` на 60 с. Смена токена в
конфиге обнуляет все cookie (значение сравнивается с текущим). TLS нет (план 01 §9): LAN —
доверенная сеть, иначе туннель.

Заголовки на все ответы: `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`,
`X-Frame-Options: DENY`; на страницу — `Content-Security-Policy: default-src 'none'; script-src
'self'; style-src 'self'; font-src 'self'; img-src 'self' data:; connect-src 'self'` (внешних
ресурсов у страницы нет, подплан 01.1 §0). CORS не включается: другим origin API не нужен.

## 3. Маршруты

### 3.1. `GET /`, `GET /assets/{*path}`

`index.html`, `manrope-*.woff2`, `jetbrains-mono-*.woff2`, `icon.svg` из `embed_dir("web")`
через `static_handler` (ETag, mime, 404). `GET /?token=…` — см. §1. Любой другой путь вне
`/api/` — `index.html` (страница сама показывает вид из `localStorage`; глубоких ссылок нет,
кроме `/#stats`, `/#cards` как якорей, которые страница читает при загрузке).

### 3.4. `GET /api/events` — Server-Sent Events

`Content-Type: text/event-stream`, `Connection: keep-alive`, через `ServerResponse.sse` и
pull-продюсер `stream_body` над `Chan` подписки у `store` (`examples/07-sse-stream`). При
подключении — сразу событие `snapshot` (текущее), затем по факту:

| `event:` | `data:` | когда |
|---|---|---|
| `snapshot` | тело §3.3 целиком | после каждого опроса любой учётки, после `POST /api/refresh`, при восстановлении из базы |
| `config` | тело §3.7 | после успешного `PUT /api/config`, после подхвата изменённого файла |
| `folders` | `{ "login_dirs": 5, "changed": ["D:/…/dev"] }` | обнаружение нашло/потеряло каталог или сменилась почта в нём |
| `notice` | `{ "level": "warning", "text": "config error: [poll] interval_sec must be a number" }` | ошибка чтения конфига, проблемы базы (подплан 01.2 §5), переоткрытие слушателя |
| `ping` | `{ "at": "…" }` | раз в 30 с при тишине |

Каждое событие несёт `id:` (монотонный счётчик); клиент присылает `Last-Event-ID`, и если
пропущено не больше 100 событий — сервер досылает пропущенные из кольцевого буфера, иначе —
свежий `snapshot`. Лимит одновременных подписок — 32; 33-я получает `503` с
`Retry-After: 30`. Соединение закрывается сервером при остановке (`event: bye`).

### 3.5. `POST /api/refresh`

Тело пусто или `{ "email": "main@example.com" }` для одной учётки. Ответы:

- `202 Accepted` `{ "queued": ["main@example.com", "…"], "expect_event": "snapshot" }` — опрос
  поставлен в очередь, результат придёт событием;
- `429 Too Many Requests` `{ "error": { "code": "too_soon", "message": "server asks to wait until 19:49", "retry_after": 95 } }` +
  заголовок `Retry-After` — пол 60 с с прошлого опроса или backoff после 429 эндпоинта
  (план 01 §0);
- `404` `account_not_found` — неизвестная почта; `409` `account_stale` — у учётки протух токен,
  опрашивать нечего.

### 3.8. `PUT /api/config`

Тело — **частичное** дерево `config` (только изменяемые ветки); сервер сливает его с текущим
конфигом ключ-в-ключ (списки заменяются целиком), валидирует как при старте, пишет файл
атомарно (подплан 01.2 §2.2) и применяет. Обязателен заголовок `If-Match: <etag из GET>`.

```json
PUT /api/config
If-Match: "a1b2c3-1725641222"
{ "poll": { "interval_sec": 120 }, "folders": [ { "path": "C:/accounts" }, { "path": "~/.claude" } ], "ui": { "accounts_order": ["work@example.org", "main@example.com"] } }
```

Ответы:

- `200` — тело как у `GET /api/config` с новым `etag`, плюс `"applied": { "restart_required": false, "listener_reopened": false }`; всем подписчикам — событие `config`;
- `400` `invalid_config` — `field` в точечной нотации (`poll.interval_sec`, `folders[2].path`,
  `forecast.work_days`), `message` — текст из подплана 01.1 §5; в теле может быть список
  `errors[]`, если ошибок несколько;
- `409` `config_changed` — файл менялся после `If-Match` (правка руками или другой вкладкой);
  тело — актуальный `GET /api/config`;
- `428` `precondition_required` — нет `If-Match`;
- `423` `config_readonly` — файл недоступен для записи (права, диск) — текст причины.

Смена `server.bind`/`port`/`access_token`: применяется переоткрытием слушателя после ответа
`200` с `"listener_reopened": true` и полем `"new_base_url"`; текущее SSE-соединение получает
`notice` и `bye`. Смена `folders` запускает обнаружение немедленно и шлёт `folders` +
`snapshot`. Изменения только `ui.*` не трогают поллеры.

### 3.9. `POST /api/folders/probe`

Проверить путь до добавления (строка «что найдено» в панели настроек, подплан 01.1 §5.4).
Ничего не пишет.

```json
POST /api/folders/probe  { "path": "\\\\wsl.localhost\\Ubuntu\\home\\me\\.claude" }
→ 200 { "path_resolved": "//wsl.localhost/Ubuntu/home/me/.claude", "kind": "single",
        "login_dirs": [ { "path": "…", "name": ".claude", "email": "work@example.org", "org": "Personal", "token_state": "ok", "same_login_as": ["C:/accounts/dev"] } ],
        "problem": null, "already_listed": false }
```

`kind` ∈ `single | parent | empty | missing`; `problem` — текст для янтарной/красной строки или
`null`. Для `parent` — все дочерние с логином. Чтение каталогов — только `.claude.json` и факт
наличия `.credentials.json` (`expiresAt` для `token_state`); содержимое токена не читается.

### 3.10. `POST /api/config/token`

Сгенерировать `access_token` (32 байта из CSPRNG, base64url). Ответ `200 { "access_token": "…",
"shown_once": true }` — единственный раз, когда токен виден в API; сервер сразу пишет его в
конфиг (с `If-Match` как в §3.8) и включает `allow_lan`, если тело `{ "allow_lan": true }`.
Доступен только с loopback: из LAN — `403` `loopback_only`.

### 3.11. `GET /api/export`

Параметры как у §3.6 плюс `format=csv|json` (по умолчанию `csv`). CSV: `at,email,kind,model,
percent,locked,resets_at` построчно, `Content-Disposition: attachment; filename="claude-limits-
2026-08-07..2026-09-06.csv"`. Потоковый ответ (`ServerResponse.stream`), без предела по
размеру. Та же выгрузка из CLI — `claude-limits export`.

### 3.12. `GET /api/openapi.json`

`openapi_handler(routes, "claude-limits", app_version)` Polaris по зарегистрированным
типизированным маршрутам (`*_typed`): схемы `Query[HistoryQuery]`, `Json[ConfigPatch]`,
`Json[ProbeRequest]` попадают в описание автоматически; примеры из этого подплана добавляются
как `x-example`. Это же описание — приёмка §8 п. 9.

## 4. Реализация в Polaris

```
server/
├── routes.nv      Router: статика (static_handler над embed_dir("web")), /api/* через *_typed;
│                  порядок middleware: security_headers → access_log → auth (только при allow_lan) → маршруты
├── auth.nv        Bearer.from_request | cookie cl_token; константное сравнение; счётчик неверных по адресу; unauthorized_bearer()
├── handlers/
│   ├── health.nv, snapshot.nv, refresh.nv, history.nv, config.nv, folders.nv, token.nv, export.nv
│   └── events.nv  подписка на Chan у store → stream_body; Last-Event-ID; лимит 32
├── dto.nv         типы ответов/запросов (serde JSON); один источник для страницы, виджета и OpenAPI
├── errors.nv      ApiError { code, message, field, retry_after } → ServerResponse с нужным статусом
└── json.nv        сериализация Snapshot → dto без токенов (тест §8 п. 2)
```

- Хендлеры не трогают базу и файлы напрямую: всё через `Chan` к файберу `store` (план 01
  §3.1) — запрос/ответ с таймаутом 5 с, по таймауту `503` `store_busy`.
- `serve_router(listener, app, ServerPolicy.new().max_connections(64).read_timeout(15s))`;
  тело запроса ограничено 256 КБ (`PUT /api/config` с сотней папок — килобайты).
- Логи доступа — `polaris.log` в формате строки на запрос без query-строки (в ней может быть
  `token=`); уровень `warn` для `4xx/5xx`.

## 5. Совместимость и эволюция

- Добавление поля в ответ — не ломающее; удаление или смена типа — `api_version + 1` и
  запись здесь. Страница проверяет `api_version` из `/api/health` при загрузке и просит
  перезагрузить вкладку, если бинарь обновился (событие `notice` со `level: "reload"` при старте
  новой версии).
- Дифференциал с эталоном (план 01, решение 10): `scripts/diff-with-probe.sh --api`
  превращает `GET /api/snapshot` в таблицу `email / kind / percent / severity / resets_at` и
  сравнивает с выводом `claude_limits.py` побайтно; поля `forecast`, `elapsed_share`,
  `*_label` в дифференциал не входят — эталон их не считает.

## 7. Примеры для скриптов

```bash
curl -s http://127.0.0.1:7391/api/snapshot | jq '.accounts[] | {email, state, limits: [.limits[] | {label, percent, reset_label}]}'
curl -sN http://127.0.0.1:7391/api/events            # поток событий, Ctrl+C для выхода
curl -s -X POST http://127.0.0.1:7391/api/refresh     # 202 или 429 с Retry-After
curl -s 'http://127.0.0.1:7391/api/history?range=30d&by=folder&step=day' | jq '.folders[].occupancy'
ETAG=$(curl -si http://127.0.0.1:7391/api/config | awk -F': ' '/^ETag/{print $2}' | tr -d '\r')
curl -s -X PUT -H "If-Match: $ETAG" -H 'Content-Type: application/json' -d '{"poll":{"interval_sec":120}}' http://127.0.0.1:7391/api/config
curl -s -H 'Authorization: Bearer <token>' http://192.168.1.10:7391/api/snapshot   # из LAN
```

## 8. Приёмка (часть Ф.2 плана 01)

Тесты — через `serve_once` без сокета (`nova-polaris/docs/overview.md`), фикстуры — из плана
01 §7; живая сеть — только `scripts/smoke-server.sh`.

1. Каждый маршрут §2 отвечает заявленным статусом и `Content-Type`; неизвестный `/api/x` — `404`
   с конвертом; `/api/snapshot` методом `POST` — `405` с `Allow: GET, HEAD`.
2. Ни один ответ (включая `500`, `notice`, `export`) не содержит подстрок токенов из фикстур;
   обратная проба — нарочно положить токен в `message` → тест краснеет.
3. `snapshot`: порядок учёток по `accounts_order`; скрытые отсутствуют без `include_hidden`;
   `severity` считается по порогам конфига (порог 50 в фикстуре делает 61 % `warning`);
   `forecast: null` для `stale`/`unknown`/`locked`.
4. `events`: первое событие — `snapshot`; `POST /api/refresh` → `snapshot` в течение тика мока;
   `Last-Event-ID` с отставанием 3 → досылка 3 событий; 33-я подписка — `503`.
5. `refresh`: второй вызов в пределах 60 с — `429` с корректным `Retry-After`; после 429 эндпоинта
   — `Retry-After` из его заголовка.
6. `history`: `7d`/`by=account` из фикстуры на 7 дней даёт `2016` точек на окно при `step=300`;
   `resets`, `locks`, `gaps` совпадают с ожидаемыми интервалами; `by=folder` при смене почты в
   фикстуре даёт два `segments` и две записи `occupancy`; `> 50 000` точек — `413`.
7. `config`: `PUT` без `If-Match` — `428`; с устаревшим — `409` и актуальное тело; с ошибкой —
   `400` с точным `field`; успешный — новый `etag`, событие `config`, файл переписан канонически
   (подплан 01.2 §8 п. 2); смена `bind` без токена — `400 server.access_token`.
8. Доступ: при `allow_lan` запрос без токена — `401` с `WWW-Authenticate`; `?token=` ставит
   cookie и редиректит; 10 неверных токенов — `429`; `/api/config/token` из не-loopback — `403`.
9. `openapi.json` валиден (проверка схемы OpenAPI 3.x в CI) и перечисляет все маршруты §2.
10. `smoke-server.sh`: поднять бинарь, `health`, `snapshot`, три события SSE после `refresh`,
    `export` в CSV с правильным числом строк, корректное завершение по сигналу.
