## 0. Что строим

Один бинарь `claude-limits`, один процесс, три режима:

| режим | что делает | кому |
|---|---|---|
| `claude-limits` (по умолчанию) | **бэкенд**: находит учётки, опрашивает эндпоинт раз в `interval_sec` (300 с по умолчанию, пол 60 с), держит снимок, отдаёт HTTP на `127.0.0.1:7391`: страницу с барами, JSON, SSE | основной сценарий: вкладка браузера или закреплённое окно браузера |
| `claude-limits --widget` (или `[widget] enabled = true`) | то же **плюс** SDL3-окно без рамки поверх других окон и иконка в трее, в том же процессе | владельцу на рабочем столе |
| `claude-limits --once` | таблица в формате `claude_limits.py` и выход | отладка, дифференциал Ф.1 |

**Страница в браузере** (образец — скриншот claude-usage-widget): тёмная, шапка с
названием, временем последнего обновления и кнопкой «обновить». Ниже — **группа на
учётку**: строка-заголовок `почта (организация) [каталог]`, под ней три бара:

| бар | источник в ответе | подпись под баром |
|---|---|---|
| Current session (5 h) | `limits[kind=session]` | `reset 20:49 (1h 52min)` |
| All models (7d) | `limits[kind=weekly_all]` | `reset Tue 12:59 (2d 18h)` |
| `<Model>` only (7d) | `limits[kind=weekly_scoped]`, по одному на модель | то же |

Процент — по центру бара. Цвет — по `severity` (`normal` / `warning` / `critical`)
и по `locked_reason`. Учётка с протухшим токеном или ошибкой сети — серая группа с
текстом причины вместо баров, не пропуск. Страница обновляется сама по SSE, без
перезагрузки; при недоступном SSE — опрос JSON раз в 10 с. Без сборки фронтенда:
ванильный JS без сборки, встроенный в бинарь файлами того же origin
(`index.html` + `app.css` + ES-модули JS — так требует CSP, разбор в 01.1 §0).

**HTTP API** (все ответы JSON, кроме страницы и SSE; полный контракт — схемы, ошибки,
события SSE, доступ из LAN, OpenAPI — подплан [01.3-api.md](01.3-api.md)):

| путь | назначение (формы тел — только в 01.3, здесь не повторяются) |
|---|---|
| `GET /` | `index.html` |
| `GET /api/snapshot` | снимок: `accounts[]` и рядом плоский `limits[]` с `account_id`, `worst`, `tz`; `ETag` — 01.3 §3.3 |
| `GET /api/events` | SSE: `snapshot` после каждого опроса, `config`, `folders`, `notice`, `ping` раз в 30 с, `bye` — 01.3 §3.4 |
| `POST /api/snapshot/refresh` | опросить сейчас: `202` или `429` с `Retry-After` — 01.3 §3.5 |
| `GET /api/history`, `POST /api/history/search` | замеры за период плоскими `series[]`, по учёткам или по каталогам; фильтр по учётке только телом `search` — 01.3 §3.6 |
| `GET /api/config`, `PUT /api/config` | настройки с `ETag`/`If-Match`; ошибки `422` с `errors[]`, `412`, `428` — 01.3 §3.7–3.8 |
| `GET /api/health` | живость, `api_version`, размеры — 01.3 §3.2 |
| `POST /api/folders/probe`, `POST /api/config/token`, `GET /api/export`, `GET /api/openapi.json` | проверка папки до добавления, генерация токена, выгрузка истории, описание API — 01.3 §3.9–3.12 |

Ошибки — RFC 9457 `problem+json` с `code` и `request_id`; в URL нет почт, путей и `account_id`;
время в UTC с `Z` (конвенция по API, подплан 01.3 §0).

Токены учёток в API не попадают никогда (README §Rules), только почта, организация,
имя каталога и проценты.

**Сеть**: в объёме плана слушаем **только `127.0.0.1`**. Доступ из локальной сети (телефон) —
отдельная фаза Ф.6 после релиза (решение владельца 2026-09-07): он тянет TLS-слушатель для Polaris
поверх `nova-tls`, сертификаты, форму входа и cookie-сессии, а закрывается виджетом и вкладкой на
той же машине. Контракт LAN-режима уже записан в подплане 01.3 (§1, §3.13), чтобы Ф.6 ничего не
переделывала: токен и TLS обязательны, вход через `/login` и `POST /api/session`, токен в URL не
передаётся. До Ф.6 `[server] allow_lan = true` отвергается валидацией конфига с понятным текстом,
слушатель остаётся на loopback; на loopback TLS нет (конвенция по API §1.1).

**Виджет** (опционально): окно без рамки, **поверх других окон**
(`SDL_WINDOW_ALWAYS_ON_TOP`, переключается из меню трея), позиция запоминается в конфиге;
внутри — та же раскладка групп и баров, что на странице; перетаскивание за шапку;
«закрыть» в шапке прячет окно. **Трей**: иконка с цветом худшего `severity` и цифрой
худшего процента; тултип — строка на учётку; меню — «Показать/Скрыть окно»,
«Открыть в браузере», «Обновить», «Поверх окон» (галочка), «Автозапуск» (галочка),
«Выход». Клика по самой иконке в API трея SDL3 нет — колбэки есть только у пунктов
меню (§2). Виджет читает снимок из памяти процесса, не через HTTP.

Данные и правила обращения с токенами — как в [README](../../README.md)
§How it gets the data, здесь не повторяются. **Правила опроса** — из эталона
`scripts/claude_limits.py` (2026-09-06), переносятся один в один:

- каталоги с одной почтой — **одна учётка** с перечнем каталогов в подписи, эндпоинт
  спрашивается один раз на учётку;
- с протухшим по `expiresAt` токеном запрос не делается: сервер ответит 401, а затем
  429 всей машине; учётка сразу помечается `stale`;
- HTTP 429 — состояние `unknown` с текстом «сервер просит подождать N с», следующий
  опрос не раньше `Retry-After` (или пола 60 с, если заголовка нет);
- `interval_sec` ниже 60 поднимается до 60 с предупреждением в лог.

| № | решение | почему |
|---|---|---|
| 1 | **Стек — Nova**, приложение = пакет Nova с `[[bin]]` | слово владельца. ## 2. UI: что рассматривалось

Требования до 2026-09-06: трей + окно на Windows и Linux одной C-библиотекой. После:
**смотреть через браузер** — основное; виджет поверх окон — опционально. Таблица
оставлена целиком: она объясняет, почему для виджета остаётся SDL3, а для основного
UI — браузер.

| вариант | трей | окно и рисование | поверх окон | цена | роль |
|---|---|---|---|---|---|
| **страница в браузере над `nova-polaris`** | нет | HTML/CSS, бары — три `div`, ноль C | нет (вкладка) | ноль нативного кода; доступ с телефона | **основной UI** |
| браузер `--app=http://127.0.0.1:7391` | нет | та же страница без интерфейса браузера | нет: окно чужого процесса | ноль | подсказка в README для тех, кому виджет не нужен |

**Почему SDL_ttf, а не `stb_truetype`** (для виджета). §5 всё равно собирает SDL3
CMake-скриптом (build-and-cache), SDL_ttf с вендоренным FreeType собирается тем же
скриптом. Взамен — хинтинг и кернинг на мелком кегле («reset Tue 12:59 (2d 18h)» на
100 % масштабе). HarfBuzz выключаем (`SDLTTF_HARFBUZZ=OFF`): шейпинг для латиницы и
кириллицы не нужен.

**Известные ограничения, которые план принимает:**

- **SDL — один поток.** `SDL_CreateTray`, `SDL_UpdateTrays` — «только главный поток».
  Решение — §3.1.
- **Linux без StatusNotifierWatcher** (GNOME без расширения AppIndicator):
  `SDL_CreateTray` возвращает NULL с `no SNI support`, фолбэка в SDL нет. Виджет живёт
  окном без трея с подсказкой в шапке; страница в браузере не зависит от этого вовсе.
- **Версия SDL.** D-Bus-бэкенд трея есть в `main`; какой релиз его несёт — выясняет
  Ф.3-спайк, возможен исход «закреплять коммит `main`». Ubuntu 24.04 (runner CI)
  пакета `libsdl3` не имеет — собираем из исходников.
- **Нет клика по иконке трея.** В `SDL_tray.h` колбэк только у пункта меню
  (`SDL_SetTrayEntryCallback`). Показ окна — первый пункт меню.
- **Wayland: нет «поверх всех окон».** SDL3 флаг игнорирует под KDE и GNOME Wayland.
  Обход — `SDL_HINT_VIDEO_DRIVER = "x11"`, окно идёт через XWayland, композиторы
  уважают `_NET_WM_STATE_ABOVE`; трей от этого не зависит. Если и так не держится —
  строка в шапке «поверх окон недоступно в этой сессии», и у пользователя остаётся
  браузер.
- **Полноэкранные приложения.** Windows скрывает топмост-окна под эксклюзивным
  полноэкранным приложением. Норма, у образца так же.
- **SSE через прокси и «спящие» вкладки.** Браузер сам переподключает `EventSource`;
  страница дополнительно опрашивает `/api/snapshot`, если событий нет дольше 90 с.

## 3. Архитектура

### 3.1. Файберы — главный инвариант

Рантайм Nova спавнит тело `main` файбером, **закреплённым за настоящим главным потоком
процесса**. **Поправка 2026-09-07 (перепроверка): ссылка была неверной.** Строку
«pinned to THIS calling … OS thread» несёт не спека, а ИСХОДНИК компилятора —
`compiler-codegen/src/codegen/emit_c.rs:30324`; в `spec/decisions/06-concurrency.md`
её нет (грепом). Разница существенна по порядку старшинства из `AGENTS.md`
(«Order of precedence»): спека нормативна, компилятор — лишь текущее поведение. То есть
главный инвариант виджета опирается на комментарий в коде, а не на D-блок, и **может
измениться без амендмента**. Поэтому он проверяется замером в Ф.0 п.4 и в спайке Ф.3
(«потоки»), а не принимается на веру; если замер разойдётся с комментарием — вопрос
владельцу с обеими цитатами (§8). Отсюда:

```
main
└── supervised {
      spawn  store          — владелец Snapshot: принимает результаты поллеров,
                              раздаёт снимок по запросу, шлёт «обновилось» подписчикам SSE
      spawn  poller[i]      — по учётке: читает файлы, HttpClient -> эндпоинт, Duration sleep
      spawn  serve_router   — accept-loop Polaris; per-connection файберы detach'атся им самим
      (main) widget loop    — только при --widget: SDL_PollEvent + рисование + Time.sleep
      (main) иначе          — ждёт завершения supervised (Ctrl+C / «Выход» из меню)
    }
```

- все `extern "C"` SDL объявляются **`#thread_affine`** (D172: вызов через границу
  `spawn` — ошибка компиляции `E_THREAD_AFFINE_IN_FIBER`). Компилятор сам не даст
  позвать SDL из хендлера или поллера;
- цикл виджета в `main`: `SDL_PollEvent` неблокирующий → отрисовка при изменениях →
  `Time.sleep(16 ms)`; при скрытом окне — `Time.sleep(250 ms)`. **Не**
  `SDL_WaitEventTimeout` и **не** `#blocking`: `#blocking` уносит вызов на threadpool
  и ломает привязку к потоку;
- `serve_router(listener, app, policy)` требует `Net Time Detach` и сам владеет
  accept-loop'ом (`nova-polaris/docs/serving.md` §Running the accept loop) — поэтому
  он в `spawn`, а не в `main`. **ЗАМЕРЕНО спайком T0.1 (2026-09-07): форма рабочая, но
  роутер обязан строиться ДО `spawn`.** Как только тело SSE получило `mut`-состояние,
  `build_router` стал мутирующим, и вызов внутри файбера компилятор отверг —
  `E_FIBER_UNSAFE_CALL` (D446), цепочка `build_router` → `serve_path` →
  `ServerRequest.header` → …; диагностика сама назвала лечение: сделать вызов до `spawn`
  и захватить результат `ro`. Это ограничение на форму, а не деталь спайка: в Ф.2
  `ro app = build_router(...)` стоит перед `supervised`, а в файбер уходит готовый роутер.
  Вердикт — [spikes/polaris-sse/VERDICT.md](../../spikes/polaris-sse/VERDICT.md);
- **общее состояние.** **Поправка 2026-09-07 (перепроверка плана): первая редакция
  утверждала «в std нет `Mutex`/`RwLock`» — это неверно.** Правило счёта было ошибочным:
  смотрели только в `std/src/concurrency/` (там действительно лишь `nvchan`, `supervisor`,
  `cancellation`, `timer`, `rate_limiter`, `retry`) и вывели утверждение обо всей std.
  Примитивы есть — модуль `std.sync`, `std/src/runtime/sync.nv`: `Mutex` (строка 1579,
  `@with_lock`), `RwLock` (1727, `@with_read`/`@with_write`), `MutexGuard` (1417),
  плюс атомики; `nvchan` сам их и использует. Значит выбор `store`-файбера — не
  безальтернативность, а решение, и держится он на своих основаниях: ОДИН владелец снимка
  (иначе два дома на один предмет), фан-аут SSE подписчикам и request/reply вместо
  блокировки хендлера на замке. Замок остаётся законным запасным вариантом, если замер
  Ф.0 п.4 покажет, что канал дороже. Polaris-примеры
  делят состояние захватом `mut`-локалов в замыканиях хендлеров
  (`examples/10-mini-service/src/main.nv:76-81`). Для нас: хендлеры захватывают
  канал к `store` и спрашивают снимок через request/reply `Chan`; SSE-хендлер
  подписывается на `Chan[Snapshot]` и превращает его в `stream_body` (образец —
  `examples/07-sse-stream`, pull-based продюсер). Могут ли detach'нутые файберы
  соединений бежать на другом OS-потоке параллельно с поллерами — вопрос Ф.0 п.4:
  если да, захват `mut` небезопасен и `store`-файбер обязателен; если нет — он всё
  равно остаётся ради SSE-фан-аута.

Ф.0 проверяет инвариант замером, а не рассуждением (§6).

**Объём привязки `nova-sdl` 0.1 — не весь SDL3** (решение владельца 2026-09-07, по аналогии с
`nova-duckdb`, подплан 01.4 §4.1). Покрыто ровно то, чем пользуется виджет: инициализация и
завершение; окно без рамки, топмост, позиция и размер, hit-test для перетаскивания, масштаб HiDPI;
рендер — очистка, прямоугольники, `SDL_RenderGeometry`, текстуры из растра и их вывод; события —
опрос без блокировки, мышь, закрытие окна; трей — иконка из растра, тултип, меню с пунктами,
галочками и колбэками; текст SDL_ttf — открыть шрифт, измерить строку, строка → текстура. Не
покрыто и добавляется по запросу потребителя минорными версиями: аудио, ввод с джойстиков и
сенсоров, камера, GPU API и шейдеры, полноэкранные режимы, буфер обмена, файловые диалоги,
шейпинг HarfBuzz (выключен сборкой), остальная 2D-графика и весь прочий SDL3. Шапка каждого
модуля пакета (`sdl.nv`, `tray.nv`, `text.nv`) и README пакета содержат этот абзац; расширение —
задача в репозитории пакета с указанием потребителя и функции.

**`claude-limits`** — приложение, чистая Nova, без своего C.

**РАСКЛАДКА: весь `.nv` — под `src/`, В КОРНЕ ПАКЕТА НИ ОДНОГО `.nv`.** Слово владельца
2026-09-07, дословно: «никаких `.nv` файлов в корне claude-limits/ не хочу». Это **строже
спеки**: спека оставляет выбор («плоская раскладка остаётся легальной… но не
рекомендуется»), владелец выбрал за нас и снял выбор. **Правило распространяется на ВСЕ
пакеты проекта, включая новые** (`nova-sdl`, `nova-duckdb` — тем же словом владельца
«и по новым пакетам что?»), поэтому их деревья ниже и в подплане 01.4 показаны с `src/`.

Проверка правила машинная и дешёвая: `ls *.nv` в корне пакета обязан быть пуст —
входит в приёмку T0.0 после переноса и в приёмку каждого нового пакета.

Основание, помимо слова владельца, — **спека, а не вкус**:
`spec/decisions/07-modules.md:1112-1122`, амендмент Plan 195 (владелец 2026-07-10)
дословно отменяет прежнее решение 2026-05-22 («отдельной `src/` и `[lib] src` нет») и
называет `[lib] src = "src"` «не legacy-совместимостью, а **стандартной раскладкой** для
новых пакетов (эталон — `nova-tls`)»; плоская раскладка `src = "."` «остаётся легальной…
но не рекомендуется для новых пакетов». Интегратор советует то же. **Почему первая
редакция ошиблась:** я взял правило из `docs/guide/authoring-a-module.md:32-34` и из
комментария `compiler-codegen/src/manifest.rs:633-635` — оба до сих пор учат отменённому
решению и согласны между собой ПОТОМУ, ЧТО состарились вместе; спека старше их обоих по
порядку из `AGENTS.md`. Расхождение заведено в реестр как **№1026** (правку делает окно
283 синхронно в английской и русской страницах гида).

### 3.3. Страница `web/index.html`

- Встраивается через `embed_dir("web")` (прелюдия, `std/src/prelude/embed.nv`) и
  отдаётся `static_handler` (`nova-polaris/docs/static-files.md`); ETag и mime — от

- Вёрстка повторяет виджет-образец: один столбец, группы по учёткам, бар — `div` с

  событий — `fetch('/api/snapshot')`; кнопка «обновить» — `POST /api/snapshot/refresh`.

артборды `*.dc.html` там же служат эталоном разметки для `web/index.html`. **Поэлементная
спецификация** — что каждый элемент значит, откуда берёт данные, как ведёт себя, формулы

## 5. Нативная часть: сборка и `[ffi]` (всё — в пакете `nova-sdl`, только для виджета)

Канон — `[ffi]` в `nova.toml` (ffi-cookbook «Build pipeline»): `.c`-шим компилирует
clang, библиотека **линкуется уже собранной**. SDL3 и SDL_ttf собираются CMake, поэтому
`vendor_src_dirs` (как у mbedTLS в `nova-tls/nova.toml`) не подходит; берём прецедент
libuv «build-and-cache»: скрипт собирает сабмодули один раз в `native/lib`, повторный
запуск — no-op по хешу коммитов.

```toml
[ffi]
c_shims      = ["native/sdl_shim.c", "native/sdl_shim.h"]
include_dirs = ["native/", "native/SDL/include", "native/SDL_ttf/include"]
libs         = ["SDL3_ttf-static", "freetype", "SDL3-static"]
lib_dirs     = ["native/lib"]
```

Порядок `libs` — от зависимого к зависимости. SDL_ttf — с `SDLTTF_VENDORED=ON` и
`SDLTTF_HARFBUZZ=OFF`; точные имена `.lib`/`.a` фиксирует спайк по выводу сборки.

Windows: только статические библиотеки, один `.exe` без DLL (решение 9а); конфликт CRT
с рантаймом Nova, если проявится, — дефект в реестр и починка. Linux: `.a` + системный
libdbus (грузится динамически самим SDL; без него — виджет без трея). Пакет тегается
интегратором (AGENTS.md «Satellite package repositories»).

**Следствие решения 3**: `sdl` — зависимость бинаря всегда, `SDL_Init` вызывается
только при включённом виджете. На безголовом Linux без дисплея бэкенд работает,
`--widget` там честно падает с сообщением SDL. Если статическая линковка SDL в бинарь
без виджета окажется неприемлемой по размеру (замер в Ф.3) — feature-флаг пакета или
второй `[[bin]]`, решает владелец по цифре.

**Запрет** (из read-project §3): ничего из `compiler-codegen/` в этот репозиторий не
копировать — рантайм и std берутся из установленного тулчейна.

### Ф.1 — ядро без UI

**ПРЕДУСЛОВИЕ (найдено перепроверкой 2026-09-07, блокирует приёмку фазы).** Вся приёмка
Ф.1 — дифференциал против эталона `scripts/claude_limits.py`, а его **нет в
репозитории**: `git ls-files scripts/` даёт единственный `scripts/probe.py`, сам
`claude_limits.py` числится `??` (untracked), а `probe.py` в рабочем дереве удалён
(`git status`: ` D scripts/probe.py`). Свежий клон получает СТАРЫЙ эталон без демона,
группировки по почте, пола 60 с и правила «протухший токен не спрашиваем» — то есть без
всех четырёх правил §0, которые фаза обязана воспроизвести. Значит первым шагом фазы (до
любого кода на Nova) эталон и лаунчер коммитятся одним коммитом: `git add
scripts/claude_limits.py scripts/start-daemon.ps1 claude-limits.example.toml` и удаление
`scripts/probe.py`; в отчёте — хеш этого коммита. Дифференциал против незакоммиченного
файла — не приёмка: он проверяет рабочий стол одного человека, а не предмет.

`accounts/` (с группировкой по почте), `usage/` (с 429), `model/snapshot.nv`,
`model/format.nv`, `config.nv` и режим `--once`, печатающий таблицу в формате
`claude_limits.py` без `--daemon`.

Приёмка: `scripts/diff-with-probe.sh` — обе программы на одних каталогах, одном
конфиге и ОДНИХ ЗАПИСАННЫХ ОТВЕТАХ; группы и столбцы `kind / percent / severity /
resets_at` совпадают; фикстура 429 — одинаковая строка состояния у обеих.
Тесты — §7, обязательны оба направления.

**Уточнение 2026-09-07, по факту написания механизма (T1.8 сделана):**

- **Сравнение не «побайтно», и «время в одном поясе» — недостаточное условие.**
  Относительный остаток («3h 13min») пересчитывается от часов при каждом запуске,
  поэтому два прогона с разницей в минуту разошлись бы ни на чём. Сравниваются ровно
  четыре названные колонки, момент сброса приводится к UTC, а остаток, бар и цвет
  отбрасываются как представление — у них свои проверки.
- **Дифференциал ОФЛАЙНОВЫЙ по умолчанию** (`--offline fixtures/usage`; `--live` —
  явным флагом). Иначе каждая приёмка тратила бы на эндпоинт два набора запросов, и
  это не теория: 2026-09-07 машина так заработала 429 (эталон, `scripts/claude_limits.py`,
  получил его на живых учётках).
- **Исходов ТРИ, а не два, и третий обязателен:** `0` — совпало, `1` — разошлось,
  **`2` — сравнить нельзя** (сторона на Nova не собрана либо `--once` не реализован).
  Замер: первая редакция скрипта, натравленная на каркас T0.0, который печатает одну
  строку версии, сказала «разошлось» — и отправила бы искать дефект в ненаписанном
  коде. Ноль сравнимых строк у одной стороны при непустой другой — это `2`, с цитатой
  сырого вывода. **Несобранная сторона не читается ни как согласие, ни как
  расхождение.**

### Ф.2 — бэкенд и страница

`model/store.nv`, `server/`, `web/index.html`, поллеры с интервалом, `POST /api/snapshot/refresh`,
`[server]` конфига: слушатель только на loopback; `allow_lan = true` или `bind` не на loopback —
`422` валидации с текстом `LAN access arrives in a later version` и строка в шапке (Ф.6).

Приёмка:
- `scripts/diff-with-probe.sh --api`: `curl /api/snapshot`, приведённый к таблице,
  побайтно совпадает с `claude_limits.py`;
- `scripts/smoke-server.sh`: health, snapshot, три события SSE после `POST /api/snapshot/refresh`,

- страница в браузере: группы по учёткам, обновление без перезагрузки — **приёмка

  `*.dc.html`, а не DOM-снимок): скриншот и строка в отчёте. Машинная часть того же

  (это как раз машинно: тест `serve_once` на состояние `unknown`);
- **негатив**: `bind = "0.0.0.0"` или `allow_lan = true` — слушатель на loopback, `422` и
  понятная строка в логе и в шапке; открытый HTTP на сетевом интерфейсе не поднимается ни при
  каком конфиге; в теле `/api/snapshot` нет подстроки `accessToken` и нет ни одного токена из
  фикстур (тест §7);
- контракт соответствует [конвенции по API](../conventions/api.md): приёмка подплана 01.3 §8, кроме
  пункта 8 (доступ из LAN — Ф.6).

### Ф.3 — виджет (опционально для пользователя, обязательно для плана)

Спайк перед фазой — **рождение `nova-sdl`**: репозиторий-сиблинг по раскладке
`nova-tls`; сборка SDL3 и SDL_ttf скриптом на Windows и Linux; шим; `extern "C"` для
`SDL_Init`/`SDL_CreateTray`/`SDL_CreateWindow`/`SDL_PollEvent`/`TTF_Init`/
`TTF_RenderText_Blended`; иконка в трее с меню из одного пункта, окно без рамки с
флагом топмост и одной строкой текста. Вердикт: релиз (или коммит `main`) SDL,
закреплённый сабмодулем; статический `.exe` собрался и его размер; трей: где появился,
где `no SNI support`; **матрица топмоста**: Windows 11, KDE X11, KDE Wayland, GNOME
Wayland — «держится / нет / с `x11`-драйвером»; в `SDL_tray.h` нет колбэка клика по
иконке (или есть — §0 дополняется); текст на 100 % и 150 % читаем — **приёмка глазами,
потому что** «читаем» измеряется человеком, а не числом: скриншот в отчёте.
**Потоки**: `main` крутит `SDL_PollEvent` + `Time.sleep(16 ms)`, поллер и
`serve_router` в `spawn`; кадры не проседают; **обратная проба**: вызов трея из
хендлера обязан дать `E_THREAD_AFFINE_IN_FIBER`. Выход — тег `nova-sdl` v0.1.0.

Фаза: `widget/`, `--widget`, `[widget]` конфига, трей с меню из §0, окно с той же
раскладкой, что страница (общий `format.nv`), топмост, перетаскивание с записью
позиции, HiDPI через `SDL_GetWindowDisplayScale`. Скруглённые бары — одна
текстура-капсула, растянутая по ширине; иконки шапки — отрезки через
`SDL_RenderGeometry`.

Приёмка: `layout.nv` — чистые функции, тесты на прямоугольники для 1/2/3 учёток и
0/1/2 scoped-моделей; сравнение со скриншотом владельца — **приёмка глазами, потому что**
эталон — картинка; окно остаётся над
развёрнутым браузером на Windows 11 и KDE X11; после перезапуска — на той же позиции;
«Открыть в браузере» открывает `http://127.0.0.1:7391`; CPU в покое < 1 %, при скрытом
окне — ниже; матрица трея: Windows 11, KDE, GNOME с расширением, GNOME без (окно без
трея, страница работает). Размер бинаря с SDL и без — цифра владельцу (§5).

### Ф.4 — упаковка

`nova build` → один бинарь на ОС; автозапуск бэкенда (реестр `Run` / `.desktop` в
`~/.config/autostart`) флагом `--install-autostart` и пунктом меню виджета; README —
установка, конфиг, как закрепить окно браузера `--app`; GitHub Actions:
`windows-latest` + `ubuntu-latest`, `nova test`, `smoke-server.sh` против записанного
JSON, сборка SDL по скрипту с кэшем. Тег `nova-sdl` v0.1.x с тем API, на который встал
виджет.

### Ф.5 — после релиза (не в объёме плана)

Уведомления по порогам (в браузере — Notification API, в виджете — трей; таблица `notification`
появляется миграцией в этой фазе, черновик — подплан 01.2 §3.14); история в кольцевом буфере
бэкенда и график на странице; виджет как отдельный процесс, читающий `/api/events` с другой машины.

### Ф.6 — доступ из локальной сети (после релиза, не в объёме плана)

Решение владельца 2026-09-07: вынесено из Ф.2 как самая дорогая часть бэкенда при небольшой пользе
для одного пользователя. Состав: TLS-вход через `polaris.serve.serve_tls(addr, tls.ServerConfig, router)` (есть в Polaris,
пример `examples/12-https`; ограничения: одно соединение на запрос, без `ServerPolicy` и
keep-alive — спайком проверить SSE и лимиты под ним, при нехватке — доработка Polaris), сертификат и его отпечаток в настройках, `/login` и `POST /api/session`,
cookie-сессии и сессионный bearer для страницы, проверка `Origin`, три уровня раскрытия
`/api/health`, обнуление путей в ответах, тумблер в панели настроек — всё по подплану 01.3 §1, §3.13
и приёмке §8 п. 8. Сюда же — перенос ключа шифрования базы из файла в хранилище учётных данных ОС
(Credential Manager, libsecret; подплан 01.2 §9).

## 7. Тесты

- **Где**: рядом с модулем, `<module>_test.nv` (канон Nova: `authoring-a-module` §5).
- **Чем**: подмена хендлеров эффектов — `Http` через `nova-http/src/client/mock.nv`,
  `Fs`/`Os` через `std/src/os/mock.nv` и аналог для `Fs`; сервер — `serve_once`
  Polaris без сокета (`nova-polaris/docs/overview.md`). Никаких сетевых тестов в
  `nova test`; живая сеть — `--once`, дифференциал и `smoke-server.sh`.
- **Фикстуры**: записанные ответы эндпоинта с вычищенными полями (`fixtures/usage-*.json`):
  обычный; `locked_reason` заполнен; `limits` пуст (фолбэк на `five_hour`/`seven_day`);
  `weekly_scoped` для двух моделей — это ТЕЛА ответов, `fixtures/usage/`.
  **Транспортные исходы вынесены отдельно (2026-09-07, при написании): невалидный
  JSON, HTTP 401, HTTP 500 и обе формы 429 — в `fixtures/transport/`.** Причина: у
  них смысл несут статус и заголовки, а тело пустое или сломано нарочно, и
  смешивать их с телами значит делать вид, что разбор тела проверяет транспорт.
  Каждый файл описывает исход целиком (статус, заголовки, тело) для мок-хендлера
  `Http`, и несёт в себе ожидаемое состояние учётки.
- **Каталоги**: обе раскладки (default с `.claude.json` РЯДОМ; `CLAUDE_CONFIG_DIR` с
  файлами ВНУТРИ), каталог без логина, токен с истёкшим `expiresAt` (запроса нет,
  состояние `stale` — мок `Http` считает вызовы: ноль), два каталога с одной почтой
  (одна учётка, оба каталога в `dirs[]`, эндпоинт спрошен один раз — правило эталона
  `claude_limits.py`), UNC-путь WSL в `accounts`.
- **429**: фикстура с `Retry-After: 120` — состояние `unknown`, `next_poll_at` через
  120 с; без заголовка — через 60 с; `interval_sec = 10` в конфиге — поднят до 60 с
  предупреждением.
- **Сервер через `serve_once`**: каждый маршрут по приёмке подплана 01.3 §8; JSON снимка не
  содержит ни одного токена из фикстур (поиск подстроки по телу); SSE-кадр — `event: snapshot`
  + `data:` с валидным JSON; конфиг с `allow_lan = true` или `bind` не на loopback — `422`
  валидации, слушатель на loopback, не паника (доступ из LAN — Ф.6).
- **База**: приёмка подплана 01.2 §8 — схема, идемпотентность «два раза подряд», занятость,
  блокировки, свёртки, целостность с ключом, `forget`, чужая база.
- **Оба направления** на каждый пункт: «делает» и «не делает» (не пишет в каталоги
  Claude Code — проверка мок-хендлером `Fs`, что записи не было; пишет только свой конфиг
  и свои каталоги данных).
- **Обратная проба** на каждую фазу — сломать условие и увидеть красный (Ф.1
  дифференциал с подменённым `percent`; Ф.2 подменить токен в фикстуре и увидеть, что
  тест «нет токена в JSON» краснеет при нарочной утечке; Ф.3 `E_THREAD_AFFINE_IN_FIBER`).

## 11. За чей счёт время

**Раздел добавлен перепроверкой 2026-09-07** — его не было, а вопрос обязателен.
**Правка того же дня по слову владельца: связь с приоритетами репозитория `nova` снята.**
Этот план ничьей очереди не ждёт и ни у чьего плана ресурс не отнимает — приоритет
задаёт владелец, а не соседний роадмап.

- `claude-limits` — **отдельный репозиторий и отдельные окна**, в worktree и ветки `nova`
  не заходит, компиляторные окна не занимает;
- **машина общая, и это единственная реальная цена.** Сборки Nova, `nova test` и особенно
  T0.5 (полная CMake-сборка репозитория DuckDB — по замеру спайка 661 с на Windows, 1196 с
  на Linux, пик RSS до 4,8 ГБ) конкурируют за CPU с чужим гейтом. Правило: перед длинной
  сборкой — спросить занятость у соседних сессий по `/peers`; во время чужого гейта своих
  сборок не запускать (норма `feedback-no-compiler-runs-during-neighbours-gate`), потому
  что «лёгкие» пробы двух окон суммируются и роняют чужой прогон по времени при зелёном
  содержании;
- **порядок задач внутри плана** — по зависимостям 01.5, а не по внешней очереди;
  длительность T0.5 названа выше, чтобы окно планировало её осознанно, а не наткнулось.
